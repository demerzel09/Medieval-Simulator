# 個人所有と制度なし環境の反事実監査

状態: 2026-09-27の設計監査。下記の制度なし環境は未実装・未計測。既存A3の固定20人90日対照を置き換えたという主張ではない。農場・市場・家はまず物理的な場所であり、それ自体が生産・販売・会計を実行する主体ではない。

## 現行A3で成立している範囲

`PhysicalObject`には物理的な親と所有者が別々にあり、取引は原子的に検証される。この物理基盤自体は個人所有を排除していない。一方、A3の世界生成・人物モデル・不変条件は4世帯、農場、市場、協同事業を前提にしている。

| 事実 | 現行の経路 | 制度を外すと |
| --- | --- | --- |
| 農作物 | 農民の収穫で協同事業所有の食料を農場倉庫に生成 | 採集可能な野生食料、本人の収穫物、現地での摂食を表せない |
| 賃金 | 請求に働いた`personId`は残るが、買物係が回収した通貨の所有者は世帯 | 働いた本人が対価の使途を判断できない |
| 通貨 | 世帯の金庫→買物係の財布→協同事業の市場金庫→買物係の財布→世帯の金庫 | 個人間での受渡し・本人の財布への保有をA3の不変条件が許さない |
| 食事 | 世帯の家にあり、その世帯が所有する食料を所定時刻に消費 | 近くに食料があっても採る・直接食べる・持ち歩く行動がない |
| 仕事 | ID順の農民当番、決まった農場/市場/荷車、固定の時刻窓 | 場所や制度を消すと判断入力と試行の成立条件を失う |

したがって「市場・農場・世帯を消し、周辺に食料資源を置く」変更は、現行A3では有効な別シナリオにならず、世界生成・検証または行動の段階で止まる。90日安定は、固定制度の運用が閉じたことの証拠であって、人物と資源だけから生活が生じる証拠ではない。世帯そのものが中央集権なのではない。**個人の所有・利用・判断が世帯と協同事業に従属し、制度なしの下位の生活経路がない**ことが問題である。

## 必要な境界

- 物の`parentId`（所在・保管）、`ownerId`（権利者）、実際に持つ人物、利用許可を分離する。本人の財布にある通貨を世帯所有とするかは契約・慣行の結果であり、物理法則ではない。
- 収穫・採集の成果物は、資源の利用権と行為から所有者を決める。農民の成果を協同事業へ渡す場合は、雇用/納品契約と実際の引渡しを経由する。無主または共有資源を扱えるようにする。
- 賃金債権はまず働いた本人に属する。支払いも本人または本人が委任した受取人へ行う。世帯への拠出や共同購入は明示的な規則・同意・行動として追加できる。
- 人物モデルの入力は「職業と指定市場」だけでなく、身体の必要、見聞きした近傍の資源、持ち物と利用権、既知の約束、可能な行為を扱えるようにする。ルール人格はその中から採集・食事・休息・取引・就労を選び、simが位置・時間・体力・量・所有権を検証する。特定の制度を共通インターフェースの必須引数にしない。
- 農場・市場・家は物理的な場所として置けるが、存在するだけで収穫・売買・保管権・会計を発生させない。「世帯」が同居人の関係を指すなら家という場所と別の任意の社会関係であり、資産の自動所有者にはしない。協同事業は人物による合意・役割・委任がある場合だけ機能する。市場がなくても、物理的に近い二人の交換は成立し得る。一方、貨幣循環は市場のない自給シナリオの合格条件にしない。

## 場所・自然・人の責務

- 場所は座標、接続、容量、地形、そこにある物体・資源の位置を表す。農場なら土壌や作物があり、市場なら人が集まれる。場所IDは売り手、雇用主、採集者、支払人の代役にならない。
- 雨、作物の成長、野生食料の再生などは時間と環境に依存する世界の物理として起こり、場所や架空の人物が「判断」したことにしない。現行の`physicalTransaction`は`actorId`と同所性を要求するため、自然生成には原因・量・保存則を検証する別の世界法則操作が必要である。
- 採集・運搬・食事・販売・通貨の手渡しは人物の試行で起こる。食料や通貨が地面や箱に置かれることはあっても、所有権の変更や別地点への移動は、実在する人物の行為・同所性・利用権を通す。市場の金庫へ売上が自動的に入る規則にしない。
- 通貨の物理正本は硬貨ロットを入れた財布・箱などの包含木に置き、持つ人物と権利者を別に記録する。個人が稼いだ金は既定では本人の権利とし、本人が受取り、保管・支出・共同資金への拠出を選べる。組織所有の金も実際の出納担当者が保管・移動し、場所だけでは払えない。
- 現行`PhysicalAuthority.ownerIds`は呼出し側が付ける権限の列で、委任の証拠や期限を物理基盤が検証していない。個人間の受渡しや組織の出納を一般化する際には、本人の同意・保管委託・役職の権限を原因付きの権利として検証し、単に呼出し側が任意の所有者IDを列挙して動かせないようにする。
- 現行`PhysicalType`は所有可能な物体に`ownerId`を必須とする。野生植物を無主の財として扱うなら、採取前は所有可能な食料ロットでなく環境資源とし、採取行為で所有権付きロットを作る方法がある。共有地の利用権などは別の規則として検証する。自然成長で人の財布や食料が増えないよう、生成と採取を分ける。

最小の因果列は「自然法則で資源が成長→本人が見つける→本人が採る→本人の荷物に入る→本人が食べる」。交換を加えると「渡す側が対価/食料を提示→相手が受ける→同所で双方の現物と所有権を確定」。雇用を加える場合も、勤務結果から債権が生まれることと、出納担当者が実在の通貨を本人へ渡すことを分ける。

## Sが市場を所有する最小商売

市場をSが所有する場所とすれば、営業・入場・保管を認める権限の帰属が明確になる。Sが自分の売上を自分の財布または市場内のS所有の金庫に保管でき、A3の「協同事業が市場で全員の売上を受け、世帯へ分配する」規則を最小対照では外せる。ただし**市場の所有は、そこにいる人、預かった食料、買主の通貨の所有を自動的に移さない**。場所は依然として判断・販売・支払いを行わない。

最初の取引形態は買い取りを候補とする。農民が自分の食料を収穫し、S本人またはSに現金と購入権限を託された運搬人が農民に代金を渡して食料を受け取る。この時点で食料の所有者がSに変わる。運搬人は荷を持って移動しても自分の所有物にはしない。市場に運んだ後、Sが買主へ食料を渡し、買主から実際の通貨を受け取る。Sが運搬人へ報酬を払うなら、Sの保有する通貨を人が手渡す。信用売買を導入する場合は現物の移転と債権を分ける。売れ残り・資金不足・運搬人の欠勤はS自身の商売に帰結する。これは実装候補であり、委託販売や共同経営を禁止する仕様ではない。

現行の汎用`site`型は`ownable: false`で、市場に単純に`ownerId: "S"`を付けると物理検証で拒否される。世界や道路まで一律に所有可能にする必要はない。S所有の市場用に、`site`タグを持つ所有可能な場所型を追加するのが小さい変更となる。その場所の所有権だけをSへ付け、金庫・食料ロット・通貨ロットはそれぞれ独立した`ownerId`を保持する。市場の所有者を変えると中の物がすべて自動譲渡される実装にはしない。

## 実装前に置くべき最小の反事実

数人と有限の食料資源点だけを置き、世帯・市場・農場・協同事業・賃金を置かない別fixtureを作る。各人が局所観察に基づいて近くの食料を採り、自分で保持・移動・消費・休息できるかを確認する。資源点の位置と人数を変え、足りない場合は空腹が上がり、他人の保有物を無断で使えず、採集担当を止めた場合に中央が代行しないことを確認する。保存再開、seed/Command再実行、食料・通貨（存在する場合）の保存、Event因果も検証する。

このfixtureは社会全体の安定を証明するものではない。次に、本人が収穫物を他人と交換する対照、任意の共同保管・世帯拠出を加える対照、事業が雇用して賃金を支払う対照を順に置く。同じ人物・物理・判断の境界で追加できれば、制度は生活の前提でなく行動の結果または選択可能な仕組みになる。既存A3は固定制度の回帰試験として残す。
