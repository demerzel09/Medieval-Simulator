# 実装判断

- 2026-09-25: 収録済み project_proposal_v0.1.md が依頼された設計書に相当するため、原本を保持して DESIGN.md に複製。新規実装、AGENTS.md なし。
- TypeScript / React / Vite / Worker / Vitest / IndexedDB を採用。Linux Node がなかったため開発環境の ~/.local/node に Node 22.16.0 を配置。依存は固定・lockfile管理。
- M0→M1→M2→M3 の順で受入テストを追加し、各段階で実行する。M3人間試遊は自動操作で代替したと主張せず、未実施として残す。
- M1: 民間賃金を初期3から2へ調整。固定食糧価格2、人口消費1では民間全員への賃金3は食糧販売収入を超え、職場資金が機械的に枯渇する。初版は国別の共同事業口座で農業・加工・輸送の収入を共同清算する。未払は日次帳票に個人別債務として保持。雇用主別市場分割・手数料は未実装範囲として明示。
- M0〜M3のID表記は短い文字列（a_0000など）。seedと外部Commandのみから通常AIも含めて再実行するreplayを用意。Command IDはイベント用PRNG/ID割当に干渉しない。
- 情報：地理は公知、遠隔部隊と占領は到着済み報告、敵は兵数の範囲推定。UIにWorldStateを送らず、本人が発していない未到着伝令の存在も隠す。現地面談は君主が移動し、その間は後続執務を遅延させる。
- 戦闘：64×64、部隊経路探索、開始時状態から双方の損害を計算して反映。各兵士IDに死亡/負傷/捕虜/士気を記録。国庫の食糧は首都発の輸送が必要で、君主が前線に移動しても瞬間移転しない。
- 金銭報酬を付けたRECRUITは実際に勝利条件付きPromiseを作る。戦利品分配は取得済み資産を専用loot口座へ移して清算。保証口座・輸送口座も保存則の合計に含める。無価値の約束を大量に履行して信用を得る抜け道はseverity=0で防ぐ。
- 日次収支は個人別の移転タプルを一つの帳票Eventに集約。約束Eventの原因配列はコピーし、後からの契約履歴追記で自己参照になることを不変条件テストで防ぐ。
- Noto Sans JPを依存に同梱し、実行時に外部フォント配信を使わない。Canvas用文字も明示ロードして日本語フォントのないLinuxでも表示する。
- npm 10.9.2のoptional peer探索がVitest更新時に内部エラーを起こしたため、`.npmrc` にlegacy-peer-depsを固定。実際に使用するReact/Vite/Vitest/Playwrightの互換性は型検査・ビルド・テストで確認。audit 0件まで更新した固定バージョンをlockfile管理。
- 90日シナリオ中のログを保持し、無期限シミュレーションは公開しない。30,000人ベンチは未対応として拒否。1,000人の計測と人間試遊の完了を混同しない。
- 設計全文の細目をすべて実装したとは扱わない。機構受入の達成と、共同市場・外交条項・兵種/医療・社会グラフ等の簡略化はSTATUSで区別する。特にM3の人間試遊が未実施の間は正式完了にしない。
- 2026-09-25: 君主の執務に既存住民の書記1人と伝令3人を各国の初期宮廷に配置。人口や新規IDを増やさない。君主Commandは同じ場所の書記が準備し、書記不在では受理しない。伝令は人物IDを持ち、道路の移動時間と前の配送先を使って手紙を運ぶ。使える伝令がいなければ発送失敗Eventとし、相手が移動した場合は配達失敗を記録する。複数宛ての同じ布告は一人の伝令にまとめる。
- 面談は「呼び出し」を既定に変更。書記の招待状を伝令が運び、対象者の信用・空腹・軍務で承諾が変わり、承諾後は伝令と同行して宮廷に到着してから2時間の面談を行う。「訪問」も選択でき、君主と書記が出向く。各段階のEventには人物IDと原因IDを付ける。
- 全住民に日次Activityを作り、収支Eventへ原因リンクを持たせる。文書作成、配送、面談、戦闘などの個別行動はEventで追う。開発モードだけがWorldの検索用投影をWorkerから要求する。通常のActorObservationへ真実を混ぜない。0.1.0セーブは読み込み時に民間人を宮廷職へ充当し、旧Command・伝令を移行する。
- 2026-09-25: A（共通実行経路）→B（軽量BDI・対人約束）→C（モデル判断）を段階移行として扱い、三段階に共通する外側の `DecisionRequestV1/DecisionResponseV1` と sim の責務を [AGENT_INTERFACES_v1.md](AGENT_INTERFACES_v1.md) に定義。判断器は人物の認識と型付き候補だけを受け、選択・制約付き計画提案・延期を返す。仕事・対人約束・動機を別概念とし、真実・資産・時間の更新と結果判定は sim のみが行う。これは実装決定であり、新契約のコード移行・テスト済みという意味ではない。行動語彙、優先度式、内部ポートの実装クラスは固定せず、交換契約の変更には版を上げる。
