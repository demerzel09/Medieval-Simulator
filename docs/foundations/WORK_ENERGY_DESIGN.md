# 仕事・体力・車両状態の小契約

状態: 2026-09-26に独立`local_food_v2`の3日fixtureへ実装。数値はこの集落の仮決定であり、旧`local_food_v1`と90日ゲームには未移行。開始・完了時に費用を一括処理する暫定方式で、道中の変化を扱う次の設計は[時間と負荷で進む行動](ACTION_PROCESS_DESIGN.md)を参照。

## 分ける資源

人物の`energy`は身体的な作業・移動の余力（0〜100）。荷車は代謝する主体ではないので体力を持たず、`cartCondition`（0〜100）を車両コンポーネントとして持つ。馬を導入するときは馬自身の身体状態・飼葉と荷車の摩耗を別に扱う。物体の重量/容量は[物体木](PHYSICAL_OBJECT_MODEL.md)、運送の案は[能力エージェント](CAPABILITY_AGENTS_DESIGN.md)、現実の支払と失敗はsimが扱う。

能力の提案にある`expectedEffort`は本人の見積りであり、本来は体力の正本にしてはならない。ただし現行配送帰路ではこの値を実支払にも使っており、見積りと実費の分離が未達。simは実物の数量・距離・担当者・残体力・車両状態を開始時に検査する。成功した仕事の体力変化は`work_effort_paid`、不足は`work_blocked`、荷車の摩耗は`vehicle_worn`を本人ID・原因Eventとともに記録する。仕事Taskを持つ人物が現地で実行した場合だけ、物体・体力・車両状態を更新する。

## 3日fixtureの数値と時点

数値は`packages/content/economy-e1-v2.json`の`labor`へ置く。抽象体力点であり、現実のカロリーではない。

| 作業・回復 | 費用または回復 | 確定時点 |
| --- | --- | --- |
| 農民の1勤務 | 8体力 | 12:00の生産時。足りなければ生産せず失敗Event |
| 運搬人の荷積み | 食料5個ごとに1体力を切上げ | 12:30。帰路の移動費も払えるか積載前に検査 |
| 荷車の帰路 | 旧E1式。21食の2kmは20体力 | 12:30の出発時。荷積み費とは別 |
| 運搬人の荷下ろし | 食料5個ごとに1体力を切上げ | 14:00。足りなければ食料は市場の荷車に残る |
| 売り手の市場勤務 | 4体力 | 14:00の勤務開始時。払えなければ販売Task失敗 |
| 買物係の購入 | 1体力 | 売買成立時。徒歩費・現金支払とは別 |
| 荷車の摩耗 | 1状態/道路km | 各出発時。2kmごとに状態が2減る。足りなければ出発不可 |
| 夜間の休息 | 最大50体力回復、上限100 | 22:00〜翌00:00の`rest` Task終了時。本人が家にいる場合のみ |

基準初日のCは05:30に家→市場で1、06:00に空車で農場へ10、12:30に21食の荷積み5と帰路20、14:00に荷下ろし5、市場→家で1を払う。体力は100→99→89→64→58、夜間休息後100。荷車状態は100→98→96。3日目の積荷は18食なので荷積み/荷下ろしは各4体力。これらの値はデバッグ画面の人物/荷車選択とEventで確認できる。

体力不足で作業を途中から無料で完了させない。荷積みと出発は同じ物体操作の前に作業費・移動費・車両状態を検査し、失敗時は食料を農場に残す。荷下ろし不能なら食料は荷車の子のまま市場に残り、世帯の食料や売上に変えない。農民が働けなければ生産しない。休息に失敗した人物の体力は回復しない。体力と車両状態は保存・再実行の対象にする。

この3日fixtureの休息は固定時間の最小実装であり、文化・仕事・睡眠欲求を一般化した[日常生活ルーティン](DAILY_LIFE_ROUTINES.md)ではない。食事の栄養と体力回復の連動、馬の飼葉、荷車の修繕/交換費、賃金、長期の疾病・疲労蓄積はE2以降の検討対象。荷車を「体力が回復する人物」として扱わない。
