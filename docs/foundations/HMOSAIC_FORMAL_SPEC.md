# 階層モデルの形式仕様（予測・適合度・評価・行動決定）

更新: 2026-10-06。区分: 実装前の形式仕様。対象は[実装前レビュー](HMOSAIC_IMPLEMENTATION_READINESS_REVIEW.md)のR01（生存評価と状態推定）・R02（適合度と不確かさ）・R03（最終選択と更新）と、R08の探索の一部である。[運用契約](HMOSAIC_RUNTIME_CONTRACT.md)が「一意に実行・対応・保存・打切りできる」形を定めたのに対し、本書は「何を計算するか」を数式で定める。調査基準: commit `88927ab`、本体v24。本体コード・fixture・同梱記録は変更していない。新構成の実行・学習・生活改善は未実施である。

数式で定義することは、レビューで未決としていた構造を選ぶことと同じである。本書は主案を一つ選び、代替と未決を併記する。主案は接続試作（レビュー順序2）の後、生活の選択（順序3）で実装する候補であり、採用は試作の計測を見て確定する。「式にすると残る問題」を[第6節](#6-式にすると残る問題)にまとめた。式は厳密さを増すが、未決を自動的には解消しない。

## 読み方と記法

- **主案**: 本書が選ぶ定義。実装するならこの形で始める。
- **代替**: 退けた理由または採用条件を付けて残す定義。
- **仮**: 数値・重み・閾値。試作の計測後に変える。
- **未決**: 式では決まらず、測定か追加の設計が必要な点。

```text
i      人物。t: 判断時点、m_t: その絶対分（運用契約と同じ軸）
h_t    本人に届いた刺激と文脈の履歴。世界の隠れた量を含まない
b_t    信念状態 b_t = β(h_t)。運用契約の人物状態の内容に対応する
c      候補（行程グラフと委譲）。C_t: 判断 t で生成した候補集合、A_t: 実行可能な候補集合
τ      候補を実行したときの本人の経過（区間ごとの状態列）
H      評価期間（分）。本人のパラメータ
⊥      未定義（unknown）。0 や確率 0 と区別する
[L, U] 区間。E_low[g], E_high[g]: 下側・上側期待値
```

## 1. 予測: 適用域付きの条件分布と区間

### 1.1 順モデル

順モデル `k` は、宣言した適用域 `D_k` の上でだけ定義される部分写像で、出力は分布の集合（クレダル集合）である。

```text
f_k : D_k → 𝒫(Y_k)            𝒫(Y_k) は Y_k 上の確率分布の閉凸集合
D_k = D_k^exp ∪ D_k^prior      D_k^exp = { x : n_k(key(x)) ≥ n_min }、D_k^prior = 事前見込みを宣言した領域
x ∉ D_k  ⇒  f_k(x) = ⊥         （適用外。0・失敗・確率 0 へ変換しない）
```

運用契約の推定の四形は、この集合の特別な形である。

```text
point     𝒫 = { δ_ŷ }                                 例: ŷ = θ_k · φ(x)
interval  𝒫 = { P : supp(P) ⊆ [L, U] }
branches  𝒫 = { Σ_r p_r δ_{y_r} : p ∈ Π }              Π は分岐確率の集合（点でも区間でもよい）
unknown   𝒫 = 宣言した範囲 [y_min, y_max] 上の全分布     （空虚な集合）

E_low[g]  = inf_{P ∈ 𝒫} E_P[g]        E_high[g] = sup_{P ∈ 𝒫} E_P[g]
```

裏付け（`Support`）は、`D_k^exp` から来たか、`D_k^prior` から来たか、外挿かと、標本数 `n_k`、条件キーを持つ。経験が無い条件で事前見込みを返すことは許すが、事前と経験を同じ裏付けにしない。

### 1.2 合成: 宣言した依存だけで因数分解する

候補 `c` の経過 `τ = (y_1, …, y_n)` について、行程グラフで宣言した依存先 `pa(j)` だけを使う。

```text
宣言した条件付き     P(y_j | y_pa(j)) ∈ f_j( x_j(y_pa(j)) )
独立を宣言した組     P(A ∧ B) = P(A) P(B)
宣言のない組         結合分布には周辺の制約だけを課す（自然拡張）
                     max(0, P(A) + P(B) − 1) ≤ P(A ∧ B) ≤ min(P(A), P(B))
```

「独立の根拠なく確率を掛けない」は、宣言のない組にはフレシェ境界だけを使うという条件になる。売却の成立 0.5 と食品提示の存在 0.5 は、独立を宣言しなければ `P(両方) ∈ [0, 0.5]` であり、0.25 ではない。0.25 を使うには `P(食品 | 売却) = 0.5` という条件付きの宣言か、独立の宣言が要る。宣言は親の構成の一部であり、その学習は[利得補足の相互作用](HMOSAIC_VALUE_AND_FEEDBACK_DESIGN.md#部分的に適用できる場合)（R07）に属する。

区間の評価を計算できるように、評価汎関数 `g(τ)` は各 `y_j` について単調方向（増加・減少・無関係）を宣言する。単調なら端点の組合せで `E_low`・`E_high` が求まる。単調でない項目（閾値をまたぐ効果など）は分岐として列挙する。予算で打ち切った分岐は空虚な集合として寄与し、区間を広げる。これが「未評価を0にしない」の形式である。

### 1.3 身体と生存の推定量

生存の基準は活動余力の経路から定義する。本人が観測できるのは感覚と活動余力であり、栄養残量ではない。

```text
e(m)        予測した活動余力の経路（body-forward の出力。区間）
T_inc       = inf { m ≥ m_t : e(m) ≤ 0 }                  活動不能に至る最初の分
生存の確率  P_low(T_inc > m_t + H),  P_high(T_inc > m_t + H)
```

`body-forward` の入力特徴（候補）は、現在の感覚（疲労・栄養需要・眠気・寒さ・活動余力・消化中）、最後の食事からの経過分、直近24時間の食事回数、所持する可食数、活動種別、荷重、屋内外、時刻である。記録ではB1のhour32の栄養需要の感覚は0で、感覚には飽和がある。同じ感覚でも履歴が違えば経路が異なるため、履歴の特徴を状態に含める。これがR01の「状態推定」の内容で、どの特徴が経路を説明するかは試作の計測で決める。

## 2. 適合度: 参照モデル付きの事後確率

### 2.1 定義

同じ役割の比較群 `K` について、入力 `x` に適用できるモデル `K(x) = { k ∈ K : x ∈ D_k }` と、参照モデル `∅` を並べる。

```text
λ_k(y | x) = π_k p_k(y | x) / ( Σ_{j ∈ K(x)} π_j p_j(y | x) + π_∅ p_∅(y) )
p_∅(y)     = 1 / (y_max − y_min)                           宣言した範囲の一様密度
λ_∅        = π_∅ p_∅(y) / ( 同じ分母 )                      全モデルが外れた度合い
```

重みの合計が1になることは「状況を説明できる」証拠ではなく、`λ_∅` が大きいときは説明できていない。事前重み `π_k` は親が渡す事前重み（運用契約の `Delegation.priorWeights`）、無ければ `K(x) ∪ {∅}` の一様とする。`π_∅` は仮に 0.1。

尤度は推定の形ごとに定める。

```text
point      p_k(y | x) = N( y ; ŷ, σ_k²(x) )        σ_k は条件区分の残差の標準偏差（n ≥ 2）。無ければ宣言した σ_0
interval   p_k(y | x) = (1 − ε) · 1[L ≤ y ≤ U] / (U − L) + ε p_∅(y)
branches   p_k(y | x) = Σ_r p_r N( y ; y_r, σ_r² )
```

逐次の更新は対数で行い、忘却係数 `ρ` と下限 `ε_λ` を持つ。

```text
log λ_k ← ρ · log λ_k + log p_k(y_s | x_s)        正規化は使用時。ρ ∈ (0, 1] は忘却（R08）
λ_k ≥ ε_λ                                         確率 0 への固定を防ぐ
```

### 2.2 用途

1. **群の予測。** `𝒫_K(x) = Σ_k λ_k f_k(x)`（クレダル集合の凸結合）。別の役割のモデルをこの群に入れない。
2. **順モデルの更新。** 混合尤度の勾配は、寄与を掛けた各モデルの勾配に等しい。

```text
∂/∂θ_k log( Σ_j π_j p_j(y | x; θ_j) ) = λ_k · ∂/∂θ_k log p_k(y | x; θ_k)
θ_k ← θ_k + η λ_k ∇_θk log p_k(y | x)
線形回帰なら  θ_k ← θ_k + η λ_k φ(x) (y − θ_k φ(x)) / σ_k²
```

[利得補足の候補式](HMOSAIC_VALUE_AND_FEEDBACK_DESIGN.md#実装可能な更新則の候補と移行)の `theta + eta * responsibility * phi * (y − y_hat)` は、この勾配の `σ_k²` を学習率へ吸収した形である。寄与は混合尤度から導かれ、任意の倍率ではない。

3. **上下の重み。** 下位の事後重み `λ` を親へ返す。親の予測器が次の `λ_{t+1}` を予測する場合、損失は `KL( λ_{t+1} ‖ λ̂_{t+1} )` とする。実装するかどうかは未決で、データ量が足りない間は固定の事前重みだけを使う。

### 2.3 R02の完了条件との対応

| 条件 | 式の上での扱い |
|---|---|
| 異なる単位 | 尤度は各ポートの単位の密度で計算し、`λ` は無次元。単位の違う出力を一つの `λ` に混ぜない |
| 観測不足 | 観測が無ければ更新しない。`x ∉ D_k` のモデルは `K(x)` に入らない |
| 全モデルの外れ | `λ_∅` で測る。閾値 `λ_∅ > λ_∅^max`（仮 0.5）で「不適合」を記録 |
| 初期重み0付近 | 下限 `ε_λ` と対数での更新 |
| 相関する子の結果 | 1.2節の自然拡張。宣言した条件付きだけが区間を狭める |

## 3. 評価: 基準ベクトルと辞書式の区間優越

### 3.1 基準（候補）

```text
u_1(τ) = 1[ T_inc(τ) > m_t + H ]                                                生存（期間内に活動不能にならない）
u_2(τ) = −(1/H) ∫_{m_t}^{m_t+H} [ w_n need(m) + w_f fatigue(m) + w_c cold(m)/c_max + w_s sleepiness(m) ] dm    累積の不快
u_3(τ) = meals(m_t + H) + κ · cash(m_t + H)                                      期間末の備蓄（κ: 主観的な貨幣→食品の換算）
```

`u_2` は状態経過の積分、`u_3` は期間末の状態である。売上・購入した食品・吸収を別々に加算しないので、同じ成果を重複して数えない。売上は `cash` か、食品を買って `need(m)` を下げる経路のどちらかにだけ現れる。重み `w_n, w_f, w_c, w_s, κ` は本人の価値観のパラメータで、運用契約の `preferenceRevision` が指す。

### 3.2 区間期待値と生存の優越

```text
候補 c の基準 j の区間   I_cj = [ L_cj, U_cj ] = [ E_low[u_j | c, b_t], E_high[u_j | c, b_t] ]
生存の優越               c ≻_1 c'  ⇔  L_c1 > U_c'1
最大集合                 M_t = { c ∈ A_t : ¬∃ c' ∈ A_t, c' ≻_1 c }
```

区間優越は推移的である（`L_a > U_b ≥ L_b > U_c` から `L_a > U_c`）。したがって `M_t` は空でない（`A_t` が空でなければ）。空虚な区間 `[0, 1]` の候補は、誰にも優越されず、誰も優越しない。未知の候補は `M_t` に残り、第二基準で扱われる。

### 3.3 第二基準と楽観度

`M_t` の中では、区間を一点に代表させて重み付きで比べる。

```text
Hurwicz の代表値   ũ_j(c) = (1 − α) L_cj + α U_cj            α ∈ [0, 1] は本人の楽観度
第二基準           V_2(c; b_t) = w_1 ũ_1(c) + ũ_2(c) + w_3 ũ_3(c)
```

`w_1` は有限で、`M_t` の中の生存の差は不快・備蓄と交換される。生存の優先は、強い意味（区間が重ならない差）では辞書式に、弱い意味（重なる差）では重みで扱う。この区別が主案の中心で、「死亡に大きな負点を置く」単一スカラーとも、完全な辞書式とも異なる。`α` は未知の候補をどれだけ有利に扱うかを決め、R08の探索の最も単純な形式になる。

### 3.4 代替

| 代替 | 内容 | 扱い |
|---|---|---|
| 制約付き | `P_low(T_inc > m_t + H) ≥ 1 − ε` を満たす候補の中で `V_2` を最大化 | 初期は全候補が制約を満たすか、全候補が満たさないかに偏りやすい。`ε` の校正ができたら主案と比較する |
| 完全な辞書式 | 基準1で区間が重なるときだけ基準2へ進む | 「重なる」が推移的でなく、循環が起こる。退ける |
| 単一スカラー | `U = −M · 1[死亡] + …` | 辞書式の選好は実数で表せず、`M` の値が判断を決める。[レビューR01](HMOSAIC_IMPLEMENTATION_READINESS_REVIEW.md#r01-本人の生存評価と推定する状態)の判断どおり退ける |
| 下側期待値だけ | `α = 0` | 未知を常に不利に扱い、探索が起きない。主案の特別な場合として残す |

### 3.5 評価期間

`H` は本人のパラメータ（仮 24時間。危機時に短くする規則は未決）。`u_3` を含めるのは、期間末直後の枯渇を期間内の評価に反映させるためである。`H` を変えたとき `M_t` と `V_2` がどう変わるかは単調ではなく、測定の対象にする。

## 4. 行動決定: 二段階の方策と更新

### 4.1 方策

```text
A_t   契約違反のない候補のうち、世界の制約として本人が知る条件（現金 ≥ 価格、容量、権限）を満たすもの
      主観的に不利なことは A_t からの除外理由にしない
M_t   3.2節の最大集合

π_w(c | b_t) = exp( β [ V_2(c; b_t) + φ_w(c, b_t) ] ) / Σ_{c' ∈ M_t} exp( β [ V_2(c'; b_t) + φ_w(c', b_t) ] )    (c ∈ M_t)
π_w(c | b_t) = 0                                                                                             (c ∉ M_t)
```

`φ_w` は学習する調整項（初期値 0）で、特徴は候補の種類・引数・条件。`V_2` は順モデルからの予測で、`φ_w` は経験からの制御の修正である。両者を分けるので、順モデルの更新と制御の更新を混同しない。`β` は仮に 2。運用契約の `ChoiceRecord.distribution` はこの `π_w` を保存する。

### 4.2 制御の更新

```text
G_2        保存した評価基準で計算した、同じ窓の観測利得（追跡台帳の observed）
V̄(b_t)    = Σ_c π_w(c | b_t) V_2(c; b_t)              選んだ c に依存しない基準価値
Δw        = η (G_2 − V̄(b_t)) ∇_w log π_w(c | b_t)
```

二択で `π = (0.5, 0.5)`、利得 `G_A = 3, G_B = 1` のとき、A の重みの期待更新は基準価値によらず `+0.5` である。[レビューR03の反例](HMOSAIC_IMPLEMENTATION_READINESS_REVIEW.md#r03-最終的な選択分布と制御の更新式)の `−0.15` は、行為に依存する任意の倍率を掛けたときに起こる。この形では倍率を掛けないので起こらない。

寄与を制御学習へ入れたい場合は、方策そのものを混合として定義する。

```text
π(c | b) = Σ_k g_k(b) π_k(c | b; θ_k)
∇_θk log π(c | b) = r_k(c, b) ∇_θk log π_k(c | b),      r_k(c, b) = g_k(b) π_k(c | b) / π(c | b),  Σ_k r_k = 1
二択の期待更新     E[ Δθ_k,A ] = η g_k π_k(A) π_k(B) (G_A − G_B)
```

`r_k` は「c を選んだことへの専門家 k の事後寄与」で、方策の定義から導かれる。各専門家の期待更新は `(G_A − G_B)` に正の係数を掛けた形になり、向きが反転しない。順モデルの適合度 `λ_k` を `g_k` に使うのはHMOSAICの仮定で、使うなら明示する。この仮定が外れても方策勾配は正しいが、「予測がよいモデルが制御を持つ」という意味づけは失われる。

### 4.3 TDを使う条件

```text
r_s = −(Δm_s / H) [ w_n need + w_f fatigue + w_c cold/c_max + w_s sleepiness ]_s      判断時刻ごとに観測した感覚
δ   = r_s + γ^{Δm_s} V̂_2(b_{s+1}) − V̂_2(b_s)                                           γ は分単位の割引。V̂_2(b) は状態の価値（第二基準の見込み累積）
```

条件は三つ。`u_2` がこの形で加算分解できること、`V̂_2` の入力に必要な履歴（例: 区間内の最大疲労）が `b` に含まれること、評価基準と方策の版が一致すること。`u_1` にはTDを適用しない。本人は自分の死亡を観測しないので（運用契約R06）、経験した収益は生存者のものだけになり、上方に偏る。生存は1.3節のモデルベースの推定に限る。

### 4.4 情報の価値

```text
VOI(c) = E_{y ∼ c} [ max_{c'} E[ V_2(c') | b ⊕ y ] ] − max_{c'} E[ V_2(c') | b ]
```

`VOI` は第二基準にだけ加え、生存の優越には入れない。計算は候補数×観測結果の数に比例して増えるので、初期は `α` による楽観で代用し、`VOI` は予算の範囲で選んだ候補にだけ計算する。情報の価値は予測であり、得た食品・現金と同列の実報酬にしない。

### 4.5 除外と記録

外部指示で置換された行為は本人の選択ではなく、`π_w` の更新に使わない。遅延した利得は、選択記録の `policyRevision` が現在と一致する場合だけ使う（運用契約の `stale-policy`）。選択記録には `M_t`、各候補の区間、`ũ_j`、`V_2`、`φ_w`、`π_w`、乱数の消費回数を保存する。

| 活動余力・疲労・栄養需要 | 21.3／26、0.181、0（消化中でない） | `energy`、`effortBody` |
| 所持 | 可食1食、現金0。穀物は畑20・自宅4 | `edibleMeals`、`ownCash`、`grainStores` |
| 売却3単位案 | 成立 0.5×0.5＝0.25、取得43・摂食44・吸収46、全14時間、疲労の峰 0.686、評価 −5.13 | `acquisition.candidates` |
| 野草地点の確認案 | 見込み 0.444、取得37・摂食38・吸収40、全8時間、疲労の峰 0.508、評価 1.44 | 同上。選ばれた案 |

1. **結合確率。** 売却成立 0.5 と食品提示 0.5 は経験0件の事前見込みで、依存の宣言がない。主案では `P(両方) ∈ [0, 0.5]` となり、v24の 0.25 は `P(食品 | 売却) = 0.5` を宣言した場合の値になる。
2. **時刻の区間。** 移動1区間につき1時間の事前の余裕が含まれているので、吸収時刻は売却案 `[44, 46]`、確認案 `[39, 40]`。どちらも `H = 24時間` の内側にある。
3. **生存の優越。** 活動余力 21.3／26、疲労 0.18、消化中でない状態から、どちらの案も期間内に活動余力が0へ達する経路を身体予測が高く見積もることはなく、区間は重なる。したがって `M_t` に両案が残り、第二基準で決まる。この段階の身体予測は試作の `body-forward@1` で計算する対象で、ここでは区間が重なるという判断だけを置く。
4. **第二基準。** 仮の重み `w_m = 2`（期間内に吸収できる食数、v24の有用食数の上限を流用）、`w_f = 1`（疲労の峰の増分）、`w_t = 1`（所要時間／H）、`β = 2` で計算した。

## 6. 式にすると残る問題

| 問題 | 式の上での現れ方 | 扱い |
|---|---|---|
| 辞書式の選好は実数で表せない | 生存を区間優越で、残りを重みで扱う二段階にした。softmax と TD は第二基準にしか使えない | 主案として採用。`w_1` の意味（生存の弱い差の交換比率）は本人のパラメータ |
| 比較不能が多い | 初期は多くの候補が広い区間になり、`M_t` が大きい。選択は `α` と `β` に強く依存する | 試作で `M_t` の大きさの推移を測る。全候補が空虚なら予備の制御（運用契約R11） |
| 未知は優越されない | 空虚な区間は `M_t` に残る。未知をどれだけ有利に扱うかは `α` だけで決まる | `α` の校正は未決。情報の価値（4.4節）は予算次第 |
| フレシェ境界は広い | 依存を宣言しないと `[0, min(p, q)]`。宣言するには相互作用のモデルが要る | 式は知識の欠落の位置を示すが、埋めない。R07の親の構成の学習 |
| 期間 `H` への依存 | `M_t`・`V_2` は `H` に単調でない。`u_3` で期間末を補うが、`H` の選び方で判断が変わる | `H` を宣言し、変えたときの判断の変化を測る。危機時の短縮規則は未決 |
| 死亡の非観測 | `u_1` は経験から学べず、モデルベースの推定に限る。活動余力0付近の校正データは生存者からは得られない | 外部監査で推定と死亡Eventを照合する。本人の推定の校正は原理的に不完全 |
| 尤度の尺度 | `σ_k` は標本2件では定義できず、事前の `σ_0` が `λ` を左右する。`π_∅`・`p_∅` の選び方が「全モデル外れ」の閾値を決める | 仮の値で始め、残差分布の計測で校正する |
| 分岐の爆発 | 分岐の数は区間数の指数。打ち切った分岐は空虚な集合になり区間を広げ、比較不能を増やす | 予算（運用契約R11）と判断の質の関係を測る |
| 単調性の宣言 | 端点で区間を計算するには評価汎関数の単調方向が要る。閾値効果は分岐の列挙になる | 評価器の版ごとに宣言する |
| 混合方策の仮定 | `g_k = λ_k` はHMOSAICの仮定。専門家が重なると `r_k` が平らになり、各専門家の学習信号が弱い | 仮定を明示し、専門家の重なりを測る |
| 方策勾配の分散と遅延 | 長い行程の利得は遅れて届き、`stale-policy` で捨てる分が出る。学習は遅い | 重要度補正等の方策差の扱いは未決 |
| TDの前提 | 感覚は判断時刻（1時間刻み）でしか観測されず、積分は近似。履歴特徴が必要 | 近似の誤差を測る。`u_1` には適用しない |
| 情報の価値の計算量 | `VOI` は候補×観測結果に比例。`α` の楽観は粗い代用 | 予算内の候補にだけ計算する |
| パラメータの数 | `H, α, β, w_*, κ, π_∅, ε, ε_λ, ρ, σ_0, n_min` が判断を決める。結果を見て調整すれば学習ではなく手直しになる | 評価を見て変えた条件は[レビューR12](HMOSAIC_IMPLEMENTATION_READINESS_REVIEW.md#r12-適応一般化生活を別に検証する)に従い学習・調整側へ記録する |
| 状態推定の特徴 | 感覚は飽和する。履歴特徴を入れても、どの特徴が経路を説明するかは式では決まらない | 試作の `body-forward@1` の残差で選ぶ |

形式化で得られるのは、どこに仮定があり、どの数値が判断を左右するかを一覧にできることである。仮定を減らすこと自体は、観測と試行からしか得られない。

## 9. 確認した計算

本書の式について、次を数値で確かめた。本体の実行や実測ではない。

- 二択・`π = (0.5, 0.5)`・利得 `(3, 1)` の方策勾配の期待更新は、基準価値 `0, 1, 2, 7` のいずれでも `+0.50`。行為依存の倍率 `(0.1, 0.9)` を掛けると `−0.15` になり、レビューの反例を再現する。
- 専門家2・候補2の混合方策で、`r_k(c) (1[c = j] − π_k(j))` が `log π(c)` の数値微分と一致する（全ての `c, k, j`）。各専門家の期待更新は閉形式 `g_k π_k(A) π_k(B) (G_A − G_B)` と一致し、基準価値によらない。
- 区間優越は代数的に推移的で、乱数の2万組でも反例がない。
- フレシェ境界: `(0.5, 0.5)` で `[0, 0.5]`（積 0.25）、`(0.5, 0.85)` で `[0.35, 0.50]`（積 0.425）。
- 第5節のB1の例の値。記録からの入力の取り出しと、仮のパラメータでの計算を分けた。

これらは式の整合の確認であり、学習の収束、生存の改善、一般化を示すものではない。
