# 食事一経路の責任・状態所有・情報到達

更新: 2026-10-24。区分: [世界と人物](WORLD_AND_PERSON_DESIGN.md)の具体化と、5人自律生活系列の限定的な境界改善。最上位は世界と判断主体である人物、HMOSAICは人物内部の方式とする。生活判断・身体係数・食品量は変更しない。

## 今回選んだ境界

同じIDの人物が世界内の身体と本人の主観状態を持つ。保存上の `VillagePerson` を二つの人物や二つの身体へ分割しない。世界側が身体・現物・配送を更新し、判断側は届いた情報の作業用複写から試みと主観更新を返す。保存JSONの同居を更新権限の共有と扱わない。

今回の実装は `advanceVillageWorld` の判断呼出しで、**入力全体と戻り値をそれぞれ `structuredClone` する**。世界が証拠として保持する `view / stimuli / subjectiveBefore` をモデルへ直接渡さない。入力の書換えは人物内部の計算であり、世界の観測記録・結果評価・保存記憶の変更にならない。記憶は返された `subjectiveUpdate` の複写からのみ確定する。返却後にモデルが参照を保持していても保存済み状態を変更しない。

これは通常のオブジェクト参照の境界であり、JavaScript実行の隔離環境ではない。外部のクロージャ等から `VillageWorld` を渡せば、その能力まで奪える仕組みではない。管理・テスト用の可変な世界APIと、人格に渡すデータの権限を区別する。

## 一食が通る関数・保存項目・Event

対象コード: [世界](../../packages/sim/autonomous-world.ts)、[身体](../../packages/sim/effort-body.ts)、[人格契約](../../packages/ai/personality.ts)、[観測・試みの型](../../packages/ai/autonomous-world.ts)。標準v24の食事と、それを共用する世界処理を照合した。

| 段階 | 関数と更新責任 | 正本として保存するもの | 本人へ到達する根拠・Event |
|---|---|---|---|
| 実在 | `VillageWorld` と世界の物理・身体規則 | `physical.objects` の所在・所有・数量、`foodLots` の食品属性・産地・期限、`people[id].effort / sleep / cell` | 監査・表示の正本。これらの構造全体は人格へ渡さない |
| 感覚 | `syncEffort / effortSensation / sleepPerception` | `effort.reserve / fatigue / digestion` 等から計算。感覚を第二の身体正本として持たない | `knownContext.effortBody` の栄養需要・疲労・消化中・荷重不快・快・軽減。備蓄実量・吸収量・消化待ちの食事ID・生理係数は渡さない |
| 観察 | `localView / observe` | `decisions.knownContext` と `observed`。発見・受信済み対象の管理項目も世界側で更新する | 携帯品、現地の自宅保管品、視野内の植物、現地の提示。`observation` 刺激が `observed` を原因に持つ。遠隔在庫の旧仕様は後述 |
| 判断 | `model.decide`、HMOSAIC等はその内部 | `subjectiveBefore / response`、採用した `people[id].memory`、世界が検査した `nextWakeAt` | `ActorInput` の複写だけを使う。`attempts / subjectiveUpdate / wait` を返す。`person_decided` に到達刺激の原因を残す |
| 試み・受付 | `advanceVillageWorld → attempt` | `decisions.chosen`、必要な `people[id].execution` | 既存の `eat` はロットIDを指定しない。世界が所持食品から既存の順序で選ぶ。外部Commandの場合も `command_submitted` を経て同じ `attempt` へ進む |
| 現物検査・消費 | `attempt(eat) → tx → physicalTransaction.remove` | 現物・食品メタデータ、`meals / eatenFood`、経験用の `needs.mealHours` | 所持先と所有から候補を選び、食欲・可食性・食数を検査。transactionが同所性・所有権・数量・予約を再検査する。成功は `ate`、失敗は `attempt_rejected`。失敗時に摂取を作らない |
| 摂取・遅延 | `ingestEffort`、世界の `effortEvent` | `effort.intake` と `digestion[{dueMinute, amount, causeId}]` | 消費成功後だけ待ち行列へ入れる。`causeId = ate.id`、期限は食事時刻+120分。即時の `effort_body_changed` は監査用。まだ栄養備蓄への吸収ではない |
| 身体時計・吸収 | `regulatedBodyHour → advanceEffortQuarter` | 15分ごとに `reserve / absorbed / lost / consumed / digestion` を更新、`sleep.minute` が身体時計 | 人格が待機していても進む。容量超過分は損失に記帳する。`body_changed / effort_body_changed` は世界の実記録。死亡後は時計も吸収も停止する |
| 結果配送 | `result → send → wakeActors` | `pending / inbox / receivedStimulusIds`、`stimulus_received`、`decisions.stimuli` | 食事成功／拒否を原因Event付き `result` として通常1時間後に届ける。対応する `experience.before / after` は世界側の自己観測から作る。成功通知は摂食の証拠であり吸収完了の通知ではない |
| 結果の記憶 | 本人の判断 → `subjectiveUpdate` | `people[id].memory` の本人の解釈・予測・目的 | 食事結果と後の感覚を根拠に更新する。`digesting` 真→偽等からの吸収は推定。世界の栄養帳簿を直接記憶へ注入しない |

一時間の処理は、世界・生態の進行、身体15分×4、行為の進行、配送と判断・試みの順。時刻Hに成立した食事は、H+1の身体進行では吸収されず、H+2の120分到達時に吸収される。食事の結果刺激は通常H+1に届く。別の刺激で起きる場合があり、`wait.at` は世界を停止する要求ではない。

既存の吸収には食事別の `absorbed` Eventや本人向けの吸収完了刺激がない。`effort_body_changed` は累計の監査値で、原因は身体更新Eventであり、吸収した食事ごとの `ate` へ直接つながらない。監査では事前の消化待ち・期限と累計差を照合できるが、本人の成果判定でこの監査値を使わない。複数食の重なりや欠測を含む成果の扱いは[成果判定契約](HMOSAIC_GOAL_OUTCOME_CONTRACT.md)に従い、未知を確定した吸収へ置き換えない。

## 更新権限

| 保存対象 | 更新できる処理 | 判断の応答ができること |
|---|---|---|
| 現物・所在・所有・予約・食品属性・消費帳簿 | 世界の行為規則、物理transaction、生育・腐敗等の世界進行 | 試みの要求。観測の数量を書き換えても現物を増減しない |
| 身体・摂取・消化待ち・吸収・死亡 | 世界の身体規則とその呼出し元 | 食事・休息等を試みる。身体の次状態や吸収済み量を応答で確定しない |
| 本人の記憶・目的・予測 | 人格が次の主観状態を作り、世界側が応答の複写を保存 | `subjectiveUpdate` の提出。入力の主観状態を変えただけでは保存されない。誤信・予測外れを許す |
| 起床・配送・実行中状態・観測証拠 | 時計・配送・世界の実行機構 | 有効な待機時刻・試みの要求。受信済みの証拠や経過時間を改変しない |

現物消費と摂取は同じ世界の食事処理で順に行う。現在の有効なfixture・食品属性を前提に、transaction成功後に既存の正の栄養量を摂取する。保存・記録は一時間の処理完了時が対象であり、任意の命令間で障害復旧できる分散transactionを実装したという意味ではない。

## 再利用・置換の判断と版

法則、物理transaction、遅延吸収、世界の受付、`ActorInput → ActorResponse` は今回の責任に合うので再利用した。入力・応答を参照で接続する部分は、複写による受け渡しへ置換した。身体・記憶の保存位置は今回の経路で二重正本を作る必要がないため同居させる。これは将来の分離・統合・削除を制限しない。

正常な既存人格の応答・状態・Eventを保つ内部改修なので、fixture / ruleset / 保存schemaを増やしていない。入力を副作用で書き換える人格の観測改変は通さなくなる。新しい判断・知覚の仕様を採用する変更とは区別し、旧版の正常な記録を再計算・再生で確認する。

次の仕様には、**現在値の観察と、場所・時刻・出所を伴う最終観察の記憶を分ける**方針を採る。遠隔の所有権だけを現在量の知覚根拠にはしない。ただしこの方針の知覚変更は今回未実装で、別fixture / ruleset / 記録を要する。具体的に残る旧仕様は次の通り。

- `fieldGrainStores / grainStores` は遠隔の自己保管庫の現在量とロットを含む。新しい所有者だから即座に知る、という根拠にはしない。
- Sの `stock_S` は場所によらず `ownLots / ownFood / edibleMeals / ownFoodLots` に含まれる。現物消費の同所性はtransactionが拒否できても、遠隔の現物を現在の感覚・携帯食として数える知覚仕様は別問題として残る。
- 現在の `eat` は世界がロットを暗黙に選ぶ。本人が記憶した特定の食品を試す契約へ拡張するかは次版で決め、拒否時に別食品へ自動置換しない条件を定める。
- 世界が具体人格の既定値・初期化・保存検査をimportする依存は残る。身体法則と人格の組立ての分離は今回行っていない。

## 受入対照と限界

[境界テスト](../../tests/world-person-meal-boundary.test.ts)は以下の独立した6対照を持つ。

1. 入力の観察・刺激の原因・届いた経験・主観作業状態を変える人格でも、同じ試みなら通常人格と世界・保存証拠のhashが一致する。未返却の主観更新は確定しない。
2. 異なる判断実装が同じ試みを返すと同じ現物・身体結果になる。保持した入力・応答参照の事後変更で確定済み状態を変えない。
3. 実際のv24の移動・採集で得た果実を使い、一食の消費、翌時刻の結果配送、待機中の120分後吸収、感覚による推定記憶、保存再開、記録再生、身体Event投影を確認する。本人に栄養備蓄・吸収量・消化待ちID・生理係数を渡さない。推定記憶を作る人格はテスト専用であり、v25への生活接続ではない。
4. 実採集後にテストが物理transactionで競合する予約を設定し、消費が拒否されて食品・摂取が増減せず、拒否結果が配送される。予約は合成した競合条件であり、二人の自律的な市場競争の実走ではない。
5. 吸収待ち中の再試行が食欲条件で拒否され、物品消費・摂取・消化待ちが二重にならない。通信の重複排除一般を証明する対照ではない。
6. 実際に食欲がある状態で、未加工穀物だけを持つ本人が可食量・空腹の入力と主観記憶を書き換えても、食事・栄養を作れない。

実行結果と未実行は[STATUS](../STATUS.md)、次の作業は[NEXT_SESSION](../NEXT_SESSION.md)に記す。全経路の情報到達監査、外部から世界参照を持つコードの封じ込め、v25食品・睡眠行程、生存改善、生活成果判定・制御学習・構成学習の採用は今回の成立範囲に含めない。
