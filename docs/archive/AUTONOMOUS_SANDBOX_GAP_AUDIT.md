# 自律的な箱庭の設計漏れ監査

状態: 2026-09-26。既存コード・設計と[開発順](AUTONOMOUS_SANDBOX_ROADMAP.md)の静的照合。**新しい実装・受入テスト・性能計測はしていない。** ここでいうP0は次の段階に着手する前に契約と対照試験が必要なもの。P1は90日または事故の結果を解釈する前に必要なもの。

## 先に塞ぐ漏れ

| 優先・段階 | 漏れと現行で起こり得る誤り | 最小の契約・対照 |
| --- | --- | --- |
| P0・A1 | **誰がいつ何を知るかが未確定。** 届いた依頼、現地観察、身体信号、物理的な雨と、全世界の真実を同じwake入力にすると、自律的に見えて先読みする。 | 刺激に発生時刻・到着時刻・観察範囲/配送経路・発信者・原因IDを付ける。本人入力は到着済みだけ。農場の真の在庫を市場にいる運搬人へ渡さず、到着/観察後だけ再計画する。届かなかった依頼でも本人が勝手に働かないことを試す。 |
| P0・A1 | **本人の持続状態と世界の行為を別々に確定すると矛盾する。** 人格v2の未解釈刺激・複数提案・主観状態更新の原子性は[仮接続監査](INTERFACE_DRY_RUN.md)でも未解決。 | 一回のwakeから採用した試行、本人状態の改訂、世界側の受理/拒否Eventを原因IDとともに確定する契約を先に決める。試行が拒否されても本人が拒否を知るまでは成功した記憶を作らない。途中保存・再実行で同一の人格状態、Task、物理結果になる試験を置く。 |
| P0・A1/A2 | **同時刻の取り合いと仕事の予約が未確定。** 7人が同じ畑枠、1台の荷車、同じ20食を希望すると、中央の処理順が隠れた配分規則になる。 | 仕事枠・道具の排他的利用権、数量予約、期限・取消し・解放、原子的な開始/終了を定める。失敗した本人へ理由を返す。二人同時要求・中断・欠勤で資源が二重使用/永久拘束されないことを試す。順番は安定だがID順の恒常的な不利を測り、必要なら公開された輪番/待ち順にする。 |
| P0・A1/A2 | **止まった人が再び動く条件が足りない。** 待機者が在庫変化を知らず眠り続けたり、同時刻の失敗を無限に再試行したりする。 | `nextDecisionAt` と本人宛て刺激の購読対象を保存。予約解放、現物到着、依頼期限、休息完了で関係者だけを起こす。再試行には期限/次回時刻/上限を設ける。未処理の必須仕事があるのにキューが空になった場合は診断Eventを出すが、simが代行して仕事を完了しない。 |
| P0・A2 | **複数人の仕事の依存関係が曖昧。** 売り手が補充を頼んでも運搬人が知らず、農民が働いても運搬人は収穫完了を知らない可能性がある。 | 売り手→運搬人、事業→農民、運搬人→売り手、売り手→買物係の依頼/受領を、同所での会話か実在する伝達行動に結ぶ。共有Taskは進捗と期限だけ持ち、各担当者が別々に承諾/辞退する。依頼不達と担当者交代で下流が変わる対照を置く。 |
| P0・A3 | **通貨が戻る物理経路と分配権が未確定。** E1では市場の金庫に代金が集まり、世帯の金庫へ瞬間移すと物体木の同所性に反する。村全体の売上40/日でも4世帯が各10を買える保証はない。 | 事業の所有・賃金・持分/扶助・未払/運転資金を整数の数表にする。支払時は市場にいる実在人物が現金を財布へ受け取り、家へ運ぶか、別の実在伝令が運ぶ。各世帯の購入10/日、給与、分配、資金源、配達時間を日別に照合し、売り手不在/受取人不在では金が移らない対照を置く。 |
| P0・A3 | **荷車保守を労働だけで永久修復できるかが未定。** 現行は毎便 `cartCondition` が減り、3日後の計画に修繕経路がない。無料全回復なら物的費用を隠す。 | A3では「調整・清掃で戻せる稼働状態」と「部品が必要な破損」を明確に分離するか、保守に使う有限の現物を導入する。実施者・作業時間・費用/部品・上限をEventに記録。90日で状態が一方的に悪化せず、担当者不在なら保守が起こらないことを検証する。 |

## 90日・事故の解釈に必要な境界

| 優先・段階 | 漏れ | 最小の契約・対照 |
| --- | --- | --- |
| P1・A3 | **「閉鎖世界」「安定」の対象が混ざる。** 現行の農作業は投入する種・水・土壌・日射を持たず、固定収量の食料を世界に生成する。通貨や所有権は閉じても、自然資源まで閉じてはいない。 | A3合格は「固定収量を明示的な外生境界条件とした食料・通貨・労働・運搬の90日運用安定」と呼ぶ。土地の無限生産を生態系の持続性とは呼ばない。作物成長と資源再生は後段で別の生成/消費法則を定める。 |
| P1・A3 | **最後に食べられたかだけでは飢えの扱いが曖昧。** 現行の`hunger`は欠食時に増えるが、労働可否/死亡とはまだ結び付かない。 | A3は食事の現物フローを検証し、空腹感や寿命の推論をしない。A4の不作では欠食日数と回復手順を測るが、生存確率の比較は身体影響を実装した後に限る。ユーザーの「安定後に空腹を追加する」順序を守る。 |
| P1・A3/A4 | **乱数と処理順の結合。** 一人の行動が増えたことで事故乱数がずれると、故障あり/なしの対照が事故以外にも変わる。 | seedを世界・人物・外部ショック等の識別子で分離するか、比較時のショック時刻/場所をCommandで固定する。同時刻の優先順・採番・保存した待ち行列を固定し、中断セーブ/再開と初めからの再実行を一致させる。複数seedの分布も見る。 |
| P1・A4 | **故障が既定の成功手順になる危険。** `cartBroken → 修理成功`という中央分岐は、判断を模倣するだけ。 | 故障は物体状態だけを変え、運搬人の観察、依頼、修理人の引受、現物調達、再開を別因果IDで追う。部品/人手不足なら停止や欠食を正しい結果にする。作業途中の進捗/荷の位置/予約を失わない。 |
| P1・全段階 | **デバッグと統計の粒度。** 90日結果だけでは隠れた中央補填、永久待機、同一人物への仕事集中が見えない。 | 人物IDから「届いた刺激→意図→試行→結果→次のwake」、物体IDから親/所有者/予約の変遷を追う。日別に作業時間、担当の偏り、空振り/待機、体力、在庫、通貨、未払、保守を集計。Event保存量と速度は別に実測する。 |

## 実装前に固定する小さな対照例

1. 同時刻にF0/F1が残り一つの農地枠を要求する。一方だけが予約し、他方は「枠なし」を知って次の判断時刻を持つ。単なるID順が毎日同じ人物の所得を削らないことも確認する。
2. 買物係が市場に到着し、売り手が補充依頼を出す。運搬人が依頼を受けずに欠勤したとき、農場在庫だけが残る。本人が依頼を受けた場合だけ荷車が動く。
3. 売買後の市場金庫に40通貨がある。会計担当と買物係が実在の場所で清算し、各世帯の金庫に戻るまで財布/運搬中の現金として一回だけ数える。
4. 荷車が農場と市場の間で故障する。積荷・所有者・通行位置・途中までの体力消費を保ったまま停止する。修理人に知らせなければ修理は始まらない。
5. 全員に依頼が届かず誰も働かない日を作る。simは食料・給与を補填せず、診断が原因を示す。翌日も無限ループ/永久予約なしで再試行できる。

これらは詳細な人格や生態系を先に実装する要求ではない。順序はA1の起床/競合/A2の依頼伝達、A3の所得/保守、A4の故障とする。
