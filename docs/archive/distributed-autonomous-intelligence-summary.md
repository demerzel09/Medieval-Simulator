# LLMと生物の知性――多階層の分散自律系へ

作成日：2026年11月4日  
本対話の結論・研究仮説・未解決課題の整理

> **中心となる問いは、「全体を毎回作り直さずに、部分が働き、学び、変わり続けられる知性をどう作るか」である。**

この文書は対話の整理であり、研究界の統一見解を示すものではない。以下では、機能についての整理、ユーザーが提示した構成上の仮説、既存研究で示された部分的な成果を区別する。

## 1. 議論の出発点

LLMの重要な成果は、次トークン予測を中心とした学習から、多様な知的能力が獲得されうると示したことである。個々の能力をすべて手作業で設計しなくても、言語の学習を通じて、知識の利用、推論、文脈内での課題への適応が生じる。

ただし、ここから次の主張がすべて確定するわけではない。

- 知性のすべてが次トークン予測だけで説明できる。
- 言語を学べば、物理環境での適応能力も十分に得られる。
- 現在の推論モデルの成果を、追加学習や環境との相互作用を含めずに説明できる。

言語には人間が世界について得た知識が含まれている。しかし、「世界についての構造を学べること」と、「ある行為に必要な構造を十分に学べること」は別である。

## 2. 理解は、目的に応じた抽象化・圧縮を含む

人間もAIも、世界のすべてをそのまま保持して扱うことはできない。目的に応じて情報を選び、何を同じものと見なし、何を重要な変数とするかを決める。

たとえばコップを扱う場合、分類には形や用途が、持ち上げるには重心や摩擦が、熱い液体を入れるには耐熱性が重要になる。

したがって、「圧縮された表現を扱っている」という理由だけでは、LLMの理解を否定できない。人間の理解も抽象化された表現を用いる。

一方、次の二つは区別する必要がある。

| 人間やシステムが設定すること | 設定だけでは決められないこと |
|---|---|
| 何を課題とするか | 実際にどんな結果が生じるか |
| 何を成功とするか | その方法で成功できるか |
| どの変数や分類を用いるか | その捉え方が新しい条件でも役立つか |

世界には、最初から試験問題と模範解答が用意されているわけではない。しかし、こちらの定義や期待に反する結果は起こる。**目的への依存と、現実からの制約は両立する。**

## 3. 理解を修正する循環

対話では、理解を次の循環として整理した。

1. 目的を置く。
2. 世界をある仕方で捉え、予想する。
3. 行動や検証を行う。
4. 結果と予想の食い違いを受け取る。
5. 行動、見積もり、または捉え方そのものを修正する。
6. 修正が有効だったかを、次の結果で確かめる。

修正には深さの違いがある。

- **行動の修正**：もっと強く握る。
- **見積もりの修正**：想定していたより重いと考える。
- **表現の修正**：握力だけでなく、摩擦・形状・材質を変数として導入する。

> 現実との食い違いが理解の修正を必要にし、表現を組み替える能力が修正の可能性を開き、その有効性を再び現実の結果が試す。

ただし、説明を変えるだけでは十分ではない。変更が、未経験の状況での予測や行動を改善する必要がある。

## 4. この循環は、人間だけのものではない

この整理は、LLMのReasoningや、LLMを核とする環境との相互作用にも当てはまる。そのため、この循環の有無を、そのまま人間とLLMの境界線にはできない。

ここでは三つを区別する。

| 循環 | 内容 |
|---|---|
| 内部での再考 | 仮説や途中結果を処理し直す |
| 環境との往復 | 行動の結果を受けて仮説を修正する |
| 経験の保持 | 発見した規則や失敗を次の判断に使う |

対話で扱ったAstraのARC-AGI-3の成果は、未知の環境から規則を獲得し、簡潔な表現を作って計画に用いる能力を検討する材料になる。ただし、成績には評価方式や推論状態の保持が関わり、内部のTransformerの自己ループが改善の原因だとは、結果だけから断定できない。

**LLMか世界モデルかという名称よりも、どの範囲で予測・計画・修正を実現できるかを調べる必要がある。** また、ゲーム内での適応から、物理世界での適応まで自動的に一般化できるわけではない。

## 5. 生物との比較で見えてきた問題

線虫、昆虫、人間には、感覚、行動、身体状態、経験が相互に関わる仕組みがある。しかし、共通する機能があることは、同一の学習アルゴリズムであることを意味しない。

生物とAIを比較するときは、システム全体を考える必要がある。

| 生物の能力を支えるもの | AIの能力を支えるもの |
|---|---|
| 進化により形成された身体・回路 | 設計された構造・入出力系 |
| 発達と個体の学習 | 事前学習・追加学習 |
| 身体・環境との継続的な相互作用 | 推論時の適応、記憶、道具、環境との相互作用 |
| 他個体からの情報や社会的学習 | 人間由来のデータや他システムからの情報 |

蜂の高度な行動は、巨大な計算設備があらゆる知的行動に必須ではないことを示す。ただし、個体の脳だけでなく、身体、他個体、環境、作りかけの巣なども成果の成立に関わる。個体の小ささと、仕組み全体の単純さは同じではない。

また、訓練の設備、一個のモデルを動かす資源、多数の利用者に提供する設備は、分けて比較する必要がある。

## 6. 中心仮説：多階層の分散自律系

ユーザーが提示した見方の核心は、生物では各段階の部分が一定の自律性を持ち、その相互作用から統合的な動作が成立する、という点にある。

適した呼称は、**「多階層の分散自律系」**である。制御の観点では「階層的分散制御」、相互作用から秩序が生まれる面では「自己組織化」が関連する。

生物に中枢的な選択や調節がないわけではない。より正確な主張は、次のようになる。

> 中枢が末端の詳細を逐一指定するのではなく、各部分が自律的に働き、上位や他の部分からの限られた調節と局所的なフィードバックによって、全体の動作が成立する。

この見方から重視する性質は、次のとおりである。

- 各部分が局所的な情報で動作できる。
- 異なる時間尺度で動く部分が協調できる。
- 通信や上位の判断が遅れても、一定の機能が残る。
- 一部を学習・変更したとき、他の部分への影響を限定できる。
- 全体の再学習を減らしながら、新しい能力を追加できる。

細胞やタンパク質の比喩では、各部分の活動が互いの成立条件を作り、全体を維持する。ただし、部分は完全に独立しているわけではなく、タンパク質も常に単機能ではない。

## 7. BPについての主張は、分けて検証する

対話では、「BPの強力さが、全体を一括して最適化する構成を促し、部分の自律性を弱めたのではないか」という仮説が提示された。

これは検討に値するが、次の三つは別の問題である。

1. **学習方法**：各部分をどう更新するか。
2. **接続構造**：どの部分と情報を交換するか。
3. **動作時の自律性**：細かな指示なしに何を遂行できるか。

BPで学習したモジュールを、疎に結合して動かすこともできる。局所的な学習則だけでは、自律性や頑健性は保証されない。また、生体の学習がBPと完全に逆の原理だと確定したわけでもない。

**BPを捨てることと、全体を毎回一括更新する必要を減らすことは同じではない。** BPを、分散自律的に動く局所規則を発見する道具として使う道もある。

さらに、モジュール化があれば必ず頑健になるわけではない。重要な接続点への依存、モジュール間の連携の失敗、学習による信号の意味の変化などが残る。

## 8. 進化を再演するのではなく、既存の能力から構成し直す

提案された方向は、生物の進化の過程をゼロから辿ることではない。

> 既存のLLMが獲得した能力を出発点に、その一部を小さな自律的な仕組みへ移し、中央への依存と全体の再学習を段階的に減らす。

既存モデルを教師、解答例の生成器、設計支援として使えば、有効な能力が存在することを足場に探索できる。その意味で、ゼロからの探索より有利な可能性がある。ただし、進化との比較で探索コストがどれだけ減るかは未確定である。

また、**構築時に集中的な学習を使うことと、動作時に分散自律的であることは両立する。** 大きなLLMを、常時必要な司令塔から、新しい能力を作る際の教師へと位置づけ直せる可能性がある。

## 9. 関連する研究候補

以下は、必要な性質の一部を実現する候補であり、全体として完成した解決策ではない。

| 候補 | この構想に使える部分 | 残る課題 |
|---|---|---|
| 技能・方策の蒸留 | 大きなモデルや教師の振る舞いを、小さな制御器へ移す | 小型化だけでは協調・継続学習は得られない |
| 実行可能な技能ライブラリ | 技能をコードとして追加・再利用し、全体の重み更新を減らす | 作成・選択を中央のLLMに依存しやすい |
| 局所的な協調規則の学習 | 限られた情報交換から集団の協調を成立させる | 個体の小型化と局所的な継続学習は別途必要 |
| ニューラル・セル・オートマトン | 全体の目標から、局所的に動く形成・維持・再生規則を学ぶ | LLMの知識・推論への適用や運用中の規則学習は別問題 |
| DNI／Synthetic Gradients | 全体の誤差伝播を待たず、各部分を非同期に更新する | 全体の学習信号への依存は残る |

構築手順の案は、次のとおりである。

1. 大きなモデルで、課題の解法と失敗時の回復例を集める。
2. 繰り返し使う能力を、小さな局所モジュールへ移す。
3. 各モジュールに、起動条件・適用範囲・助けを求める条件を持たせる。
4. 限られた通信で協調する規則を学ばせる。
5. 環境の変化には、関係する部分の更新で対応する。
6. 中央への問い合わせを減らしながら、性能が保たれるかを検証する。

## 10. 最も重要な未解決課題と評価方法

最大の難所は、**一部分が学んでも、他の部分との協調が壊れないようにすること**である。内部を変更しても、外部とのやり取りの意味や約束をどう保つかが問題になる。その約束自体を変える必要がある場合の調整も残る。

したがって、正答率だけでなく、以下を測る必要がある。

- **中央への依存**：問い合わせ回数、通信量、停止時に残る機能。
- **更新の局所性**：一部分の変更に伴い、どこまで再学習が必要になるか。
- **継続的な適応**：新しい能力の獲得と、既存能力の保持を両立できるか。
- **部分障害への耐性**：モジュールの故障・通信遅延時に何が維持されるか。
- **再結合可能性**：既存の技能を新しい組み合わせで使えるか。
- **総資源**：部分の計算だけでなく、通信・協調・保守まで含む費用。

本対話で到達した研究上の問いは、次の形にまとめられる。

> **既に得られた知的能力を、局所的に働き、学び、変更できる単位へ移し、それらの協調によって、中央への依存と全体の再学習を減らせるか。**
