# 経済新設計の実装前監査

状態: 2026-09-25時点の文書・コード照合。ゲームコードは未変更。[経済閉路の設計](ECONOMY_LOOP_DESIGN.md)を実装する前に何を確定すべきかを示す。**E0（現行90日の基準記録）は[実施済み](ECONOMY_E0_BASELINE.md)**。以下の「E1前」「E2前」は、その段階の世界状態・受入fixtureを確定するための条件であり、将来の全職業や人格モデルを先に完成させる要求ではない。

## 20人fixtureの数字で見つかる未確定点

農民`7→7→6`人が日量`3`を作れば、3日で`21+21+18=60`食になり、20人の3日需要60食と一致する。これは**食料総量の検算のみ**。初日の生産が食事時刻までに市場と4世帯へ届くかは、道路・勤務・積載・買物の時刻が必要である。初期世帯備蓄で初日をしのぐなら、その備蓄が尽きた後の配送継続を検証する。

固定価格2なら毎日40通貨が世帯から事業へ移る。税・費用なしの7人勤務日には賃金18、残余22を戻せるが、4世帯それぞれが10通貨の購買力を得る分配は自動ではない。既定の80%家計拠出なら個人口座へ残る20%もある。**合計40が戻ること、各世帯が買えること、事業の運転資金が日初に足りることは別の条件**である。E2のfixtureは各世帯の労働者、事業持分/扶助権、初期の通貨・食料、日ごとの追加拠出を数表にしてから受入値を定める。

基準例では「人が不在」「金がない」「道が塞がる」のいずれかを変えると、配送・販売・食事・所得のどこが切れるかをEventで説明できる必要がある。予測や動的価格を追加してから欠落を覆うべきではない。

## 実装の入口と完了判定

E0は現行の複数seed・90日を読み取り専用で走らせ、日別の生産/消費、世帯別食料・通貨/欠食、共同事業口座、装備在庫、職名と実働相当の差を記録する。現行コードに実働時間はないので、**職名からの生産を「実働」と報告しない**。E0の記録形式、seed、シナリオ、ゲーム版を固定する。

E1前の7項目は[具体契約](ECONOMY_E1_CONTRACT.md)に仮決定した。実装受入は「同じ人物が二つの仕事をしない」「産地から市場へ運ばない限り販売できない」「現物と通貨の予約/取消しが保存則を破らない」「失敗と代役を人物ID・原因Eventで追える」「保存再開と再実行で一致」の対照で行う。E1の独立fixtureは初期資金だけで3日を回し、賃金循環をまだ持たないため、**経済が自律的に閉じたとは報告しない**。

E2の開始までに事業主体・分配・運転資金・実働と生産上限を定める。20人fixtureは少なくとも日31〜90に食料の実生産・実輸送・売買・各人の食事が続き、初期備蓄の純減、未払債務の累積、どの世帯かの購買力の継続的な減少を隠さないことを検査する。全世帯の安定を要求するfixtureにするなら、分配制度もその条件を満たすよう明記する。不平等や欠食を意図するfixtureなら、観測された結果と設計上の期待を一致させる。

保存形式は現行`schemaVersion: 1`/`engineVersion: 0.2.0`からどう移行するかをE1の本編適用前に決める。移行中の既存セーブに対しては、変換可能な範囲を検証して変換するか、理由を明示して読込を拒否する。暗黙に在庫の所在地や進行中Taskを捏造しない。人格v2全体の未解決契約（未解釈刺激、複数提案、主観状態更新の原子性）は[仮接続調査](INTERFACE_DRY_RUN.md)で追い、E1にはまず経済Taskの依頼・引受・試行・結果の最小境界を使う。

E1以降の1,000人性能、保存量、人間試遊はまだ測っていない。基準計測値を新しい設計の達成値に読み替えない。

## 現段階では固定しないもの

可変価格、融資、市場間の投機、すべての職業のレシピ、土地売買、天候・収穫変動、睡眠/排泄の細かな効果、NN/LLMの内部構造は、E1の在庫・取引・時間の契約を決める条件ではない。新しい財や身体効果を追加する段階で、その所有・生成・消費と検証を別に定める。これらを空のEventや仮の収入として先取りしない。
