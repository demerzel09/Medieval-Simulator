# 現行の設計原則

更新: 2026-10-24。開発の目的と実行境界を記す正本。具体的な採用条件は[DECISIONS](DECISIONS.md)、実装・検証の事実は[STATUS](STATUS.md)、次の作業は[NEXT_SESSION](NEXT_SESSION.md)。整理前の記述は[履歴](archive/DESIGN_HISTORY_2026-10-03.md)に保存した。

## 目的

人物が本人に届いた情報、身体の必要、記憶、文化、利害、他者との関係から行動を選び、その作用と世界の制約から生活・仕事・交換・協力や対立が生じる世界を作る。世界の状態と因果が整合して進行することと、各人の生活が持続することをそれぞれ検証する。資源不足、誤認、拒否、破産、欠食、死亡も結果として残す。

中央が仕事・食料・所得・価格・人口を目標値へ補正しない。まず食品の生産・採集・加工・運搬・売買・食事の小さな連鎖で原理を確認する。次に技能獲得と需要に応じた職選択を加え、持続する経済を目指す。政治・外交・戦争の新規拡張はこの基盤の後に扱う。固定の90日完走だけで、人格・人口・地理の異なる条件への一般性を証明したとはしない。

## 最上位の枠組み

最上位の抽象化は**世界**と**判断主体である人間（人物）**とする。人物は世界の中に身体を持ち、世界も人物も同じ物理的な制約に従う。世界は実際の状態変化と行為の成立を確定し、人物は届いた情報と記憶から行為を試みる。身体の実状態・本人の感覚・本人の予測を区別する。

全体図と現行コードの対応は[世界と人物の設計](foundations/WORLD_AND_PERSON_DESIGN.md)、参考にした構成と相違は[コロニー系実装の比較](foundations/COLONY_SIM_ARCHITECTURE_REVIEW.md)を参照する。HMOSAICは人物内部の判断方式の一つであり、世界全体の最上位構成ではない。

[食事一経路の契約](foundations/WORLD_PERSON_MEAL_CONTRACT.md)で、関数・保存項目・Eventと更新権限を具体化した。世界は身体・現物・配送・観測証拠を更新し、人物は届いた情報の複写から試みと主観更新を返す。身体と記憶の保存JSONが同居していても、入力の書換えで世界の証拠や身体を変更できない受け渡しとする。遠隔の自己所有だけでは現在量の知覚根拠にならず、次の知覚仕様では現在の観察と出所・時刻付きの最終観察記憶を分ける。旧版の遠隔在庫仕様の変更は別版で行う。

**既存実装の維持は制約ではない。** 現在のクラス・関数・保存の配置を前提にせず、責任が枠組みに合うかで再利用・置換・統合・削除を判断する。既存の法則・記録と比較可能性を保ち、意図した挙動変更を版で明示する。下記の時計・配送・制度は二つの最上位概念を支える責任で、独立した第三の判断主体ではない。

## 実行境界

| 境界 | 責任 |
|---|---|
| 人物の判断 | 届いた刺激、感覚、文化、記憶、技能、目的、約束から行動・受諾・拒否・待機を選ぶ。rule／NN／LLM／人間は内部の実装方式で、全方式に同じ採点式を強制しない |
| 世界法則 | 生育・劣化・身体の消耗と回復、位置・移動・容量、物品・貨幣、権利・現物の検証と試行結果を確定する |
| 時計・情報配送 | 進捗、起床、競合順、宛先と到達時刻を管理する。未観察の世界状態や未来の正解を本人に注入しない |
| 社会関係・制度 | 当事者の行動で作られる所有・利用権・約束・債務・役割の記録と制約。世帯・家・農場・市場が人格なく行動や分配をしない |

物の所在と所有者を分け、権利があるだけで現金や物品を自動移転しない。全住民・兵士は固有IDを持つ人物として扱う。判断、試行、受理・拒否、進捗、納品、支払、失敗を因果Eventで追い、保存再開・同じ入力からの再現を検証する。`packages/sim` というディレクトリ名だけで、既存の中央phaseや日次経済をこの境界に準拠した実装と扱わない。

## 複雑さを制御する抽象化

新しい目的・予測方式・学習方式を加えるとき、理解・変更する範囲を限定する。オブジェクトは担当する状態と不変条件を守り、役割ごとの契約で協調する。人格の外側は既存の`ActorInput → ActorResponse`を維持し、内側は予測、制御、合成、評価・選択、分析・学習を独立に差し替えられる構成にする。状態を持たない計算は純粋関数でよく、クラスの数や継承の深さを目的にしない。

モデル定義、人物ごとの学習状態、呼出しごとの委譲・意図を分ける。基本モデルは親の目的名や職業へ依存せず、必要な主観情報と要求だけを受ける。実行器は進行・予算・確定を担当し、食品確保や回復の個別判断を持たない。状態の更新は所有者の検証済み操作を通し、保存はJSON、実行時の振る舞いは登録した実装から復元する。

抽象化の成立は、親を追加しても基本モデルと実行器を変えずに使えること、予測器と制御器を別々に差し替えられること、状態・観測・時間・版の不変条件が保たれることで確認する。経験によるモデル内の構成変更は学習対象に残し、登録定義の変更・今回の再計画と区別する。責務・変更権限・試作の対照は[オブジェクト設計](foundations/HMOSAIC_OBJECT_DESIGN.md)、運用の正本は[運用契約](foundations/HMOSAIC_RUNTIME_CONTRACT.md)を参照する。この境界を実装した[v25の接続試作](baseline/HMOSAIC_CONNECTION_V25_RESULT.md)では追加・差し替え・再現を確認した。仮の評価と経験平均は生存比較・制御学習・構成学習の成立を意味しない。

現在の達成度は[実装図と不足の整理](foundations/HMOSAIC_OBJECT_DESIGN.md#現在の抽象化と実装図)を参照する。v25には共用・差し替えの土台があり、実行器の状態直接変更を所有者へ移し、改訂検査と凍結した読取を実装した。さらに通常のモデル呼出しを宣言した相手・役割・契約に制限し、モデル別の入力codecで必要な項目へ投影する。一方、所有者間の追跡変更と分析器の登録簿参照が残る。抽象化は部分実装である。今後の生活行程を増やす前に、目的の観測可能な完了条件と、これらの責任・権限を具体化する。[成果判定の契約](foundations/HMOSAIC_GOAL_OUTCOME_CONTRACT.md)で行為・行程・成果・価値を分ける。仮の「到着完了」は食品取得・吸収や身体回復の達成を意味しない。

## 身体と本人の予測

帰宅・睡眠・食事は身体と環境、本人の知識から選ぶ。帰宅回数や決まった日課を成功条件にしない。栄養供給、活動疲労、睡眠不足、眠気、寒さ、現在の荷重の不快、快と負担軽減を区別する。休息で栄養を生成せず、現金を直接身体へ変換しない。

強い快・不快と通常の経過を経験として記憶し、似た状況の将来と対処時間を予測する。状況別の小モデルについて、予測の信頼と行動の価値を分け、対応した本人の実結果で更新する。未選択の結果は仮説として残す。現在の不快の解消を強く優先し、目的を達成できる見込み・期限・代替があるときに有限の我慢を選ぶ。研究上の参考、初期方策の重み、学習した見込み、物理係数を混同しない。

## 実装の範囲を判断する資料

現行の標準は食品取得の共同比較と死亡処理を含む5人の自律生活v24。具体的な身体・食品・所有・死亡条件は[DECISIONS](DECISIONS.md)、測定値と未達は[STATUS](STATUS.md)。本編M0〜M3、E1／A1〜A3、旧個人市場などは別系列の回帰資料で、その完走・利益を現行の持続経済の証拠にしない。

人格の外側の契約は[自律行動契約](foundations/AUTONOMY_INTERFACE_CONTRACT.md)と[人格設計](foundations/AGENT_INTERFACES_v2.md)、所在・容量・所有は[物体モデル](foundations/PHYSICAL_OBJECT_MODEL.md)を必要時に参照する。初版企画や長期設計は[foundationsの案内](foundations/README.md)から読む。将来機能の記述を実装済みと判断しない。
