# E0: 現行経済の90日基準計測

状態: **E0実施済み**。現行simの経済的な振る舞いを記録した比較基準であり、[新経済の閉路](ECONOMY_LOOP_DESIGN.md)の達成結果ではない。ゲームのルールと世界状態更新コードは変更していない。

## 再現条件と成果物

- シナリオ `pass_and_harvest`、人口1,000人、90日。engine `0.2.0`、content hash `d623749e`。
- 無策のseed `240924`、`42`、`71`、seed `240924`の外交と軍事の計5ケース。外交・軍事の外部Commandは既存の`runner.ts`と同じ手順で、詳細成果物に保存した。敵の通常AIは全ケースで稼働する。
- 日0は`newGame`直後（初期徴兵後）。各日末に全250世帯の食料・通貨・生存/空腹人数、各口座区分、職名人数、Activity区分、日次生産/消費と`economy` Eventの仕訳集計を採取する。
- 実行: `npm run economy:baseline`。人が読める[要約](../artifacts/economy-e0-summary.json)と、全5ケース×90日の[詳細JSON（gzip）](../artifacts/economy-e0.json.gz)を再生成する。展開例: `gzip -dc artifacts/economy-e0.json.gz > /tmp/economy-e0.json`。

「食料の世帯移転」は現行`dailyEconomy`の国別共同事業口座→世帯への仕訳であり、実在の売り手や運搬人を経た配送ではない。職名と`Activity(work)`は勤務時間の実測ではない。`unpaid`はその日の賃金不足の報告で、返済すべき債務の保存台帳ではない。口座残高には所在地がない。以下の「空腹人日」は食事を逃した回数ではなく、日末に`hunger>0`だった人物の延べ数。

基準seed・無策の共同事業口座では、食料が日0の5,000から日30の12,246、日90の23,351へ増えた。同じ日に軍務中の人物には空腹があり、日31〜90の民間Activityでは空腹は0だった。**余剰食料の存在と必要な人への到達は別問題**である。90日目は日次食事処理の後に一部が復員するため、日末の`military`フラグだけで空腹者を分類すると69人を民間人に誤分類する。上表はその日のActivityで分類した。

装備は全5ケースで日31〜90の消費0。生産した装備が共同口座に蓄積する。現行の商人はActivityに`work`と記録されるが、`dailyEconomy`には商人による集荷・販売・輸送の処理がない。食料の移転額と運搬人の実働を結ぶ因果記録もない。

通貨総量は各日100,000で保存されたが、これは各家計の継続可能性を意味しない。基準seed・無策では、日0→90に国庫通貨30,000→20,405、全世帯の家計通貨40,000→19,075、個人口座0→33,050、共同事業口座30,000→26,208となった。売上で共同事業口座の賃金がまかなえていても、国庫と家計の推移、実配送と実働は別に評価する必要がある。日31〜90の賃金不足報告は全5ケースで0だったが、後日の未払返済まで検証したという意味ではない。

## 検証と限界

`npm run typecheck`成功、`npm test`は5ファイル28/28成功。計測コマンドを二度実行し、要約JSONとgzip詳細のSHA-256が両方一致した。既存90日シナリオの最終世界ハッシュは無策`196a22c8`、外交`f7a1dca6`、軍事`bb7b2ab0`で従来の記録と一致。5ケース×90日の各日で、全財について「口座合計＝日0口座合計＋累積生産－累積消費」を確認し、各日1,000件のActivity要約が存在した。

複数seedは無策経路のみで、外交・軍事は基準seedだけ。価格・賃金・初期資産を変える感度分析は行っていない。今回の経済計測は処理時間やブラウザ性能の測定ではない。民間物流・勤務時間・賃金債務が未実装なので、このデータからそれらの性能や健全性を推定しない。E1では同じ基準条件と比較しつつ、運搬人不在・資金不足・欠勤による結果差を新たに検証する。
