# 自律的な箱庭を先に成立させる開発順

状態: 2026-09-26の開発順。A1の最小fixtureとA2の買物係・売り手・農民・運搬人の縦断面は[実装済み](STATUS.md)。次は食事・休息と家への荷下ろし、その後に保守/会計を本人主導へ移す。A3〜A4と20人の全員自律経済は未実装。対象は独立した20人・4世帯のE1物体木版。既存90日ゲームの軍事機能は回帰確認の対象として保ち、箱庭の自律性が成立するまで軍への新規接続を進めない。

実装前の[漏れ監査](AUTONOMOUS_SANDBOX_GAP_AUDIT.md)で、本人へ届く刺激、仕事/道具の競合、永久待機の防止、通貨の物理配送、保守の資源境界を追加した。A1〜A4はこの監査の該当対照を通してから次へ進む。

五要件の共通接続面は[自律行動の外側のインターフェース](AUTONOMY_INTERFACE_CONTRACT.md)に定めた。A1の実装時にはこの境界を小fixtureで検証する。これは設計であり、受入済みのコードではない。

## 到達したい最初の状態

農民、運搬人、売り手、買物係が、本人に届いた仕事・目に見える在庫・自身の予定から行動を選ぶ。simは時計と物体・通貨・所有権の正本を持つが、「今日はF6が休み、12:30にCが21食積む」という全員分の脚本を実行しない。本人が働かなければ生産されず、運ばなければ販売されず、買物係が行かなければ家に食料は届かない。平常時にこの連鎖と所得循環が長期間続いて初めて、偶発的な故障・不作へ進む。

ここでの「自律」は高度な予測能力ではない。本人に属する持続的な意図・簡単なルール・局所的な再判断で仕事が続くこと。人格v2の同じ入力/出力境界を使い、ルール、後のNN/LLM、人間の代行を世界側の法則と混ぜない。[行動中の状態](ACTOR_EXECUTION_DESIGN.md)と[動力による進行](ACTION_PROCESS_DESIGN.md)をこの箱庭で先に検証する。

現行E1には食料を毎日1つ消費する仕組みと単純な `hunger` 値がある。これは現物・需要の検証に必要な最小状態として残すが、空腹感による判断・疾病・排泄・人間関係の新規モデルは、経済閉路が安定するまでは追加しない。食料以外の野生資源や軍事もこの段階の合格条件に入れない。

## 誰が何をするか

| 主体 | 本人に届く入力と簡単な既定判断 | 世界側で確定する結果 |
| --- | --- | --- |
| 世帯の買物係 | 家の在庫・支払可能額を見て、必要なら注文/買物を試みる | 持出した現金、移動、受領した食料、代金の清算 |
| 売り手 | 届いた注文と現物の市場在庫を見て、補充を依頼し販売する | 注文・予約、受渡し、通貨移転 |
| 農民 | 届いた需要、農地の空き、本人の時間/余力から勤務を選ぶ | 実働の仕事量に応じた生産と在庫増加 |
| 運搬人 | 届いた依頼、現地で見た荷、荷車の状態から積載/配送を選ぶ | 実積荷、道中の進捗、体力、到着した現物 |
| 保守担当 | 荷車の実際の状態と担当仕事を見て保守を試みる | 保守に使った時間・労働と車両状態の変化 |
| 事業の会計担当 | 実売上と契約/世帯持分を見て、賃金・分配を実行する | 既存通貨だけの移転と未払債務 |

保守と会計は「世界が無料で直す/配る」機能にしない。最初は既存住民の兼務でよいが、本人ID、Task、時間、動力費、権限、因果Eventを残す。軽い車輪の調整を労働だけで表すならその限定を明記する。部品交換が要る故障を入れるときは実在する部品と調達経路を先に用意する。水車・馬・牛の実装は、この箱庭の初期合格には必要ない。

中央のキューが行うのは、起床予定・本人へ届く注文/観察/結果・物理的な完了候補の配送と、同時刻の原子的操作の整列だけ。職業に応じた仕事内容は本人のルール/ルーティンが決める。全人物を毎分走査して次の職を割り当てない。協同事業の注文や賃金規則は制度として存在してよいが、実行者と資金源を省略しない。

## 「安定」の受入条件

安定は実装の前提として埋め込まず、観測する結果とする。受入時は、人物の判断を止める、特定の担当者へ依頼を届けない、資源を不足させる、といった反事実で下流の変化を確認する。同じ数量・納期が中央の職業別処理から再現された場合は、自律的に安定したとは判定しない。

最初は20人で90日、故障や不作の新しい偶発ショックなし。固定seedの一例だけでなく、複数seedと保存再開で検証する。事前に定義した需要・資源量で、少なくとも日31〜90の毎日に実働、食料の実生産、実配送、現物と通貨の交換、各人の食事があること。全20人が食べられる基準fixtureを用意するが、それを達成するためにsimが不足を自動補填しない。ここで確認するのは**固定収量を境界条件とした90日の運用安定**であり、土壌・水・種・季節を含む無期限の生態学的持続性ではない。

村全体で食料が足りても、家ごとの支払能力や所在が足りなければ失敗。通貨総量、所有者別残高、食料の `初期＋生産－消費－明示損失`、予約、輸送中の荷、本人の時間/体力を日ごとに照合する。少なくとも日31〜90に、初期通貨/食料の取り崩し、未払債務、保守不足が一方向に蓄積していないことを日別推移で確認する。事業の売上は実在の買主の支払から生じ、賃金・世帯への分配はその実在通貨の範囲に限る。価格は最初は固定でよい。

安定は「日末の在庫と残高が毎日同じ」という意味ではない。勤務休みや3日周期の小さな振動は許す。長期の悪化傾向、外部からの無記録補充、同じ人の二重勤務を許さない。初期資金が多いから90日耐えたという結果は閉路成立と数えない。期間末だけでなく後半の日別のフローと世帯別残高を表示する。

構造的な反事実も必須。特定の農民/運搬人/売り手/買物係を欠勤させたら、それぞれの作業と下流結果が実際に変わること。代役を立てるなら**別の実在人物の判断・移動・時間・作業Event**を示す。中央処理がその人を飛ばして同量の食料を生成/配送するなら不合格。

## 安定後の偶発トラブル

基準世界が上記に合格してから、同一seed/同一初期状態に一つずつ故障・不作を注入する。事故の発生そのものは世界の真実として決定的に保存し、本人には見聞きした時だけ伝える。故障では荷車と食料が最後の実在地点に残り、運搬人・売り手・買物係が各自の情報に基づいて停止、報告、保守、代替手段を選べる。不作では産出量が実労働より少なく、農民/売り手/世帯が不足を順に知る。最初の対照は「影響が正しく伝播し、二重資産や瞬間修復がない」こと。**すべてのショックから必ず復旧することは要求しない。** 復旧できた場合は使った人手・物資・通貨・時間を示し、できなければどの制約が閉路を切ったかを示す。

ショックの注入は受入用の外部Commandまたはseed付き世界イベントとし、人物の意思決定と混同しない。平常時/故障時/不作時の差を同じ観測指標と因果Eventで比較する。雨・賊などはその後に同じ割込み境界へ追加できる。

## その先の生存実験へ残す要件

木・動物・採集を追加するときも、有限な物体/場所、成長・移動・捕獲/採取の世界法則、各個体の局所認識と行動、作業量と時間、所有/利用権、食べられるまでの実物流通を分ける。植物の成長や雨には意思を仮定しない。動物は必要に応じて単純な行動主体と動力源を持つ。資源が全員分に足りなければ、不足・協力・争い・移住・死亡は各個体の制約と行動の結果から発生させ、「弱い者から消す」という中央ルールで結論を先取りしない。結束や戦闘力の効果は将来の独立した対照で比較する。

## 実装順

1. **A1: 自律行動の小fixture。** 人物の意図/現在行動/次回判断時刻、局所的な刺激、本人ルール、仕事量の進行、保存再開をE1とは別の小さな試験で実装する。中央の時刻処理を世界法則と配送に限定する。
2. **A2: E1の役割を本人主導へ移す。** 現物・通貨・家・仕事の既存正本を使い、買物係→売り手→農民→運搬人→保守/会計の順に中央の固定時刻分岐を置き換える。既存3日ケースは回帰比較として残すが、旧21/21/18便数やハッシュを新設計へ強制しない。
3. **A3: 平常90日。** 賃金・世帯分配・運転資金・保守の閉路を作る。日別/世帯別の指標と欠勤反事実で安定を判定し、20人で結果を固定してから人数を増やす。既存90日軍事ゲームは変更せず回帰テストだけ行う。
4. **A4: 偶発トラブル。** 荷車故障と不作を別々に注入し、本人への伝達、局所的再判断、資産・時間・費用、成否の差を確認する。条件が異なる複数seedで再現する。
5. **A5以降:** 身体的空腹の精密化、人間関係、他資源と野生動物、土地の再生、集団間競合へ進む。軍事拡張は箱庭で必要な行動・資源機構を検証した後に再開する。

A1〜A5は今回の**新しい作業順の名前**で、完了済みのE1/E2/E3やM0〜M3を改名しない。A1小fixtureとA2買物係・売り手・農民・運搬人のみ実装・検証済み。A2の生活行動と保守/会計、A3〜A4のコード、90日安定値、ショックの結果、性能値は現時点では存在しない。
