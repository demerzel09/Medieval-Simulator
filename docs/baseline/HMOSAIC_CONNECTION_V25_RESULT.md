## 実装した接続と抽象化

[新しい人格](../../packages/ai/hierarchy/village-adapter.ts)は本人の入力を必要な主観情報へ投影し、実行器の試行を既存の世界行為へ変換する。[fixture](../../fixtures/hierarchy-v25.ts)はv23の物理設定を複写し、`hierarchyModel.compositionVersion = travel-body-prototype@1`だけを追加した。v24の変更は食品判断なので、物理設定はv24とも同じ。rulesetは`autonomous-village-hierarchy-v25`、保存先は`memory.hierarchy`。標準画面・既存人格を置き換えない。

| 所有者 | 実装と変更の境界 |
|---|---|
| [ModelRegistry](../../packages/ai/hierarchy/registry.ts) | 役割別実装と入出力・状態codecの対応。不変の定義、単位・観測／予測・投影・循環・身体ポートを検査する。構成検査は`compile`にまとめ、別のCompilerクラスは作らない |
| [DecisionSession](../../packages/ai/hierarchy/session.ts) | 判断内の入力＋モデル改訂によるキャッシュ、参照来歴、共通予算。入力と状態は複写・再帰的凍結を通す |
| [ExecutionState / ModelStateStore](../../packages/ai/hierarchy/state.ts) | 目的・行程改訂・委譲・意図の遷移と参照、人物×モデルの更新・経験重複防止・旧状態の保持。行程の改訂原因・時刻・証拠参照を保存する |
| [TrackingLedger](../../packages/ai/hierarchy/tracking.ts) | 証拠対応、遅延・欠測・曖昧さ・終了理由、予算で延期した証拠と更新。予測／制御／寄与の信号を区別する |
| [合成器](../../packages/ai/hierarchy/composer.ts) | 有限グラフと分岐、資源の検査、予測上の時刻と身体の一度だけの更新 |
| [HierarchyRuntime](../../packages/ai/hierarchy/runtime.ts) | A結果対応の確定、B計画→C選択→D応答。B〜Dの例外は未確定状態を捨て、Aと失敗記録を残す。世界へ渡す行為のcodec検査も確定前に行う |
| [具体モデルと構成](../../packages/ai/hierarchy/models.ts) | 予測、制御、合成、仮評価、仮選択、診断、経験平均、予備応答を登録する。親名・具体モデルIDの分岐を共通実行器へ置かない |

`travel-forward@1`、`body-forward@1`、`travel-control@1`、`compose@1`を、`recovery-parent@1`と`food-parent@1`から共用する。学習状態は人物×モデルに一つ、委譲・意図は呼出し別。子の差し替えは契約IDを持つ構成の別名参照で行う。登録関数は具体型のcodecと実装を結び、動的呼出しの文字列IDは実行時codecで検証する。全呼出しをコンパイル時に証明する型付きグラフ生成器は実装していない。

予測器・制御器を独立に差し替え、第三の親を追加しても共通実行器や基本モデルを変更せず動かせることをテストした。評価と選択も別登録にし、仮の最大値選択を共通実行器へ埋め込まない。これは限定した拡張対照であり、将来のあらゆる行程に必要な抽象化が完成したという意味ではない。

## 採用した運用と仮の計算

点・範囲・分岐・未知を保存し、未評価を数値0へ変えない。枝ごとの状態を分け、未到達の枝は`unknown`のまま残す。時刻の範囲加算は行うが、分岐した時間の一般的な依存計算は`unknown`へ戻す。正式なクレダル集合の計算ではない。

局所予測は移動時間と、疲労・活動余力等の本人の身体感覚。身体は疲労、活動余力、栄養需要、眠気、寒さ、吸収中を別ポートとする。初期値は主観的な仮の見込みで、世界の身体処理を呼ばない。移動の完了時間と観測できた身体変化率を`sample-mean@1`で経験平均へ更新する。中断した移動は完了時間の教師にせず、身体変化は観測した区間だけを使う。飽和や回復中の栄養変化など、単純率の教師にできない観測は除外する。

保存した旧モデルに実入力を入れ、全残差を局所残差と上流入力の予測外れによる波及に分ける。テストの疲労例は全体0.14＝局所0.10＋上流0.04。診断で計算した後状態を、将来の行程へ再適用しない。同じモデル・実経験の複数出力は一更新にまとめ、二つの親の共用で学習が重ならない。

| 計算・判断 | 今回の仮仕様 |
|---|---|
| 親の行程 | 本人が知る回復先／食品地点への移動→観察。到着を完了条件にする。食品取得と回復そのものはまだ行程化しない |
| 仮評価 | `temporary-goal-v1`。回復の優先度は`10×疲労＋寒さ`、食品は`10×栄養需要＋1`。そこから予測時間（時間）と`3×疲労増分`を引く |
| 仮選択 | `temporary-selection@1`。評価済みの最大値を選び、同点はID順。乱数状態を人物別に保存するが、今回の消費数は0 |
| 中断rule | 移動中、寒さ8以上または疲労0.86以上で中断を提案する。初期固定ruleであり、経験で獲得した適応とは扱わない |
| 親利得と制御 | 完了観測と数値的な利得を区別する。到着しても利得は`unresolved: goal-complete-value-unmeasured`。制御信号は保存するが更新しない |
| 寄与 | `unknown: R02-not-adopted`。任意の寄与係数を制御更新へ掛けない |
| 構成変更 | 登録された構成は不変。行程改訂とモデルの経験平均更新はあるが、経験による子・引数・順序の変更は未実装 |

追跡は実行状態と別に持ち、六つの終了理由を保存する。食事後の吸収はロットの確定IDが届かないため推定にとどめ、別の食事が重なると`ambiguous`にする。期限後の結果は`late`で学習しない。分析・更新予算が足りない証拠を次回へ残す。B〜Dで失敗してもAで確定した更新は保つ。
