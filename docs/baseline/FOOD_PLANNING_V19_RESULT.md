# 食料の需要・期限・採集競合と短い行程比較 v19

更新: 2026-10-03。[v18](FOOD_JOURNEYS_V18_RESULT.md)の後続。[予測と行動選択の設計](MODULAR_PREDICTION_AND_ACTION_PLAN.md)のCを食品の確保へ限定して具体化した。物資・現金・生育周期・睡眠時間・移動速度の世界規則は増やしていない。薪・雇用・技能獲得・職選択は停止／未実装を維持する。

## v18の食事間隔を監査した結果

- Fの最長72時間の間隔はhour1351〜1423、Cの82時間はhour130〜212。穀物を直接食べたことで成立した食事ではない。
- Cはhour152、156、180、205、Fはhour1380、1384、1408で採集を開始したが、完了時の「plant not ready」で食料を得られなかった。同じ植物を先に収穫した人物がいて、植物が再生待ちになっていた。v18全体には同じ理由の失敗60件がある。
- 他人の現在地は見えるが、その人がどの植物を採集中かは判断入力にない。植物の量を観察した時点で、すでに別の採集作業が進んでいても同じセルを選んでいた。
- Fはhour1366に食料探索へ出発し、翌判断で睡眠不足を理由に帰宅した。次の食事需要が近いと判定しても、その前に睡眠と採集・帰路の時間が入ることを一緒に比べていなかった。

一度の食料枯渇や帰宅を必ず失敗にはしない。実際の食品の入手、身体負担、食事時刻を人物ごとに測る。

## 実装した判断

### 見える採集作業を使う

世界は本人の観察範囲にいる人物の採集対象・数量を `visiblePlantWork` として渡す。遠隔の作業や予約、他人の在庫、今後の植物の量は渡さない。人物はすでに他人が採集中の植物を候補から避ける。予約制度や優先権を追加する機能ではなく、動物による減少や観察後の競合は引き続き起こり得る。

移動中の他人の目的は渡さない。同程度の食品候補には[人物別の安定した選択順](../../packages/ai/personal-choice.ts)を使い、費用へ0.05未満の初期の差を加える。記憶した探索先の同条件の候補も同じ順で比べる。同じ順位の行先へ全員が向かい、到着後に追いかけるように行先を変える集中を減らす。無作為な行動の試行や学習済みの嗜好ではなく、再実行できる初期方策である。旧版は従来の順を保つ。

### 次の食事と睡眠の前に確保する

[食品行程](../../packages/ai/food-planning.ts)は、本人に届いた情報から以下を比べる。

- 観察した成熟植物5候補、観察／記憶した家の食品、現地の購入提示、既知の市場の再確認、記憶した植物セルの探索。合計最大8候補。
- 移動と採集／取り出し／購入、その後の判断と帰宅に必要な時間。移動時間と体力には既存の本人の経験モデルと未経験の初期見込みを使う。
- 現在の空腹、需要時計から次に食料が必要になる時刻、8時間の睡眠を挟む余裕。食事後の経過と需要時計は区別する。
- 取得後の荷重、帰宅までの体力、寒さの予測、睡眠不足。採集は当初3食以内の目安とし、大きい量が身体の余裕に入らなければ1食まで減らす。

条件がよい間に食品を確保し、行程全体が起きていられる時間を超える場合は家で先に眠る。食品を持つ人が寒い屋外で食事を続けると悪化が見込まれる場合は、食料を家へ運ぶ候補を選ぶ。出発後も新しい観察と身体で判断し直す。

家では、食料確保に不要な重い荷物を先に預ける。全荷物を持った往復が不可能だからという理由で待ち続け、既存の荷卸し判断へ届かなくなる順序を修正した。製パン担当の加工用穀物はこの不要物にはしない。食品が未確認の市場の一候補が危険でも、それだけで記憶した植物の探索まで停止しない。

探索先にも移動・確認・帰路の身体負担を見積もる。到着時に食品があるとは数えず、食数は0・根拠は記憶とする。初期試走では探索だけが比較を通らず、空腹時に夜間の出発→採集見送り→帰宅を反復する状態が発生した。採集先を実際に再観察する必要と、出発の条件を待つ必要を同じ比較へ接続した。

候補の費用は、需要時刻に対する遅れ、所要時間、体力、寒さ、睡眠不足を得られる食数あたりで比べ、記憶・未確認の余裕を加える。1食だけの採集を反復して他の作業時間を失う問題に、小さな備蓄の効率を反映した。**重みと閾値は初期の方策であり、快不快から学習した行動価値ではない。** 汎用の行動列探索や人格からの継続Process中断まで完成したものではない。選択した最初の一行動だけを世界へ試行する。

現行の比較式は `(遅れ×4 + 行程時間 + 体力×0.25 + 寒さの最大値×0.5 + 終了時の睡眠不足×0.1) / max(1, 食数)` に、記憶2・未確認8の費用と個人の選択順を加え、同じ採集目的の継続は0.5引く。移動・体力・気温の見込みは本人の観測で更新するが、この重み自体は今回学習しない。身体の余裕・量・期限・競合の条件を満たした候補の中から費用の低いものを選ぶ。

探索は可否の検査に使い、食品の取得を保証しない探索が既存の耕作・仕入れ・加工を先に置き換えない。観察した植物や家の実食品・購入提示を確保できればそれを選び、そうでないときは探索の身体の余裕を確認して既存の目的判断へ接続する。初期試走で探索が製パン担当の仕入れを常に遮り、パン生産が0になる状態を検出して順序を修正した。

### 期限と保管先を区別する

携帯品は次の需要時刻まで使える食品を数え、穀物やその前に腐る食品を食事備蓄にはしない。家の食品は家にいるときの観察を記憶し、遠隔では記憶として再確認する。到着時の観察が記憶を更新する。購入候補の期限も現地提示から得る。

市場の再確認は現在の食品があるという保証ではなく、候補の期待食数は0・根拠は未確認とする。本人が現金を持つことと、購入できる原料が実在することを区別する。製パン用の原料が実際にある場合は既存の加工判断へ接続し、現金だけで採集の比較を省かない。

未成立の穀物売却と食品購入の用途を区別し、用途が変われば連続失敗をリセットする。売却の待機中だからという理由だけで、食料確保のための市場確認を何日も延期しない。食品購入自体が未成立だった再訪間隔は維持する。

### 寒さと回復の経験を条件に合わせる

v19は屋外の寒さの集計を、昼夜に加えて本人が観察した冷たい／暖かい空気で分ける。区間の両端で条件が異なる経験を単一の率へ混ぜない。寒さ0・上限48、睡眠不足0で観測が制限された結果から、潜在的な変化率をそのまま更新しない。

予測の余裕は各時間の変化率へ反映し、身体の下限も各時間で適用する。暖まって寒さが0になる時間の不確かさを最後にすべて加え、後の寒さが必ず増すように扱わない。これは初期の余裕であり、安全保証や校正済みの予測区間ではない。

家の食品の記憶は最大40ロット、行程候補は最大8。比較が必要な判断だけに候補を保存し、備蓄が使える間の待機判断へ同じ比較表を複製し続けない。今回の試走でも全文JSONがNodeの文字列上限を超える状態があり、不要な比較記憶を残さないようにした。長期・大人数の記録の差分化は後続。
