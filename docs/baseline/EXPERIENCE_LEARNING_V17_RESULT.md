# 食事の実時計・目的を持つ運搬・行動経験 v17

更新: 2026-10-02。[v16の行動監査](V16_BEHAVIOR_AUDIT_AND_LEARNING_PLAN.md)に続く実装。初期の食料・現金・収量・生育周期は増やしていない。世界が実行結果を確定し、本人は届いた結果で見込みを更新するという原則を継承する。

## 実装した範囲

| 監査の順 | 今回の実装 | 残る範囲 |
| --- | --- | --- |
| 1 時計・積み込み | 食事からの実経過と需要周期を分離。販売する余剰、現金の目的、運搬体力から積む量を選ぶ | 予定行程の途中で食料が必要になる時刻まで含めた比較 |
| 2 行動と実結果の対応 | 移動・休憩・睡眠・採集・農作業・加工と、即時の収納・購入・食事を同じ対応記録で扱う | 任意の複合行程への成果配分 |
| 3 経験と候補比較 | 初期の体力見込みと状況別の経験モデルを、同じ実結果で比較。経験に応じて運搬量と出発前の回復判断を変える | 快不快・時間・成果の統合評価、回復場所や作業先の全面的なモデル競合 |
| 4 短い目的の列 | 採集先への移動から現地採集まで目的を保持。観察した植物セルの再訪、市場待機の区切りを追加 | 期限と販売実績の学習、生産量・探索先・職の選択への統合 |

技能獲得・職選択、雇用、木こり、薪は今回の実装に含めない。市場が持続的に循環したという受入にもしていない。

## 身体の時計

新規則の `mealHours` は、実際に食べた時点で0になり、その後の時間を数える。食事前の55時間を24時間の循環へ丸めない。初期値18は開始前の食事からの経過の仮定であり、開始前の実観測ではない。

別の `needClockHours` が従来の24時間周期の食事需要を数える。食べても需要の周期を消さず、既に溜まった空腹は一食ずつ減る。先の食料必要性には、この周期と実経過・現在の空腹を使う。食後の経過だけを見て、まもなく増える需要を見落とす処理にしない。旧版は元の循環時計・規則で再現する。旧記録の画面では「食事周期（旧記録）」と表示する。

## 目的を持った積み込み

- 売る余剰がない播種予備だけを、市場へ運ぶために取り出さない。播種分は本人の保管庫に残せる。
- 販売は、携帯現金の既存の目安8までを得る初期の目的に合わせる。売れたことや他人の需要を仮定しない。
- 自宅の寒さ予測で出発を見送る間は、売却分を先に積まない。食品の必要が迫る場合も、積む前に食料確保を選ぶ。
- 最大5単位までの候補を、容量と本人の体力見込みで比較する。重すぎる見込みなら量を減らすか回復する。実物の容量・所有・現地・穀物保存則は世界が引き続き検査する。
- 播種用の取り出しは、観察した耕作済み区画などの用途につなげる。穀物1を消費して播種し、20を収穫する既存の物理規則は継承する。

荷卸しそのものを禁止しない。新しい身体・食料の条件で、積んだ品を預け直す選択は可能である。

## 行動と結果の対応

[対応記録・更新](../../packages/ai/action-learning.ts)、[人格への接続](../../packages/ai/learning-needs.ts)、[世界側の実行結果](../../packages/sim/autonomous-world.ts)を追加した。

1. 選択時に行動予測IDを発行し、身体、重量、現金、食事分、携帯・保管の原料総数と、初期・経験の体力変化率を固定する。
2. 世界は実際に選ばれた試行の開始状態を保存し、継続作業ではProcess IDを接続する。
3. 結果に開始・終了状態、実経過、完了・失敗・中断・拒否・置換を付け、本人へ届ける。
4. 本人は予測ID、行動、開始時刻・状態、試行・Processの対応を確認して更新する。別Process、重複、未到達の配送で更新しない。

収納・購入・食事などの原子的な変更の実経過は0時間。次に判断できるまでの時間と、物理的な実行期間を混同しない。収穫20は携帯品に入らなくても本人の保管原料の増加として記録する。積み替えは本人の原料総数を増やさない。購入時の支出や食品の増減も結果に残る。

体力の誤差は、行動前に固定した変化率を**実際に観察できた区間**へ適用した値と、実変化との差。移動時間の誤差は既存の経路別予測台帳で別に扱う。途中失敗や行先変更の区間から消耗を学んでも、その期間を到着までの時間として学ばない。回復が体力の上限に達した区間、消耗が0へ達した区間から、観測できない変化率を推定しない。

外部コマンドが人格の提案を置き換えた場合は、元の予測を除外する。結果が届かない予測も未観測として閉じ、成果0で埋めない。記録末尾の継続作業は結果待ちのまま残る。

## 小さなモデルの競合

最初の消耗率は、世界の階段状の移動消費式を使わず、重量に対する滑らかな初期見込みと寒さ・睡眠不足の余裕から始める。経験モデルは実観測の平均を `平均 += (観測 − 平均) / 件数` で更新する。

条件は「行動・重量4単位の範囲・屋内外・寒さ8以上・睡眠不足24以上」。移動の条件キーに物品名を入れない。同じ重量の穀物と他の荷物は同じ消耗モデルを使う。食べられるか、播種に使うかなどの物品の違いは別の行為の条件として扱う。

両方の予測が存在した同じ区間について絶対誤差の平均を比較する。少なくとも経験2件・比較2件があり、経験モデルの誤差が初期モデル以下なら経験の率を使う。危険をよく予測するモデルも保持でき、不快な結果だったことだけでモデルを捨てない。

運搬・出発前の回復には、この率を接続した。移動時間は引き続き既存の経路・荷重別台帳を使い、未経験の距離見込みには既存の距離式が残る。快不快から任意の行動評価やモデル構造そのものを学ぶ仕組みまで完成したものではない。

本人ごとの新しい記憶は、未決予測8・直近結果4・条件モデル16・植物の場所12まで。全行動の証拠は保存記録の判断・刺激・Eventに残る。長期間の判断記録へ無制限の記憶を複製すると保存JSONが大きくなりすぎるため、人格が保持する要約を制限した。

## 採集と市場

以前に本人が観察した植物セルを再訪し、到着して収穫可能か確かめる。記憶の在庫を現在の実在庫とは扱わない。周辺が枯れていれば、観察済みの別セルへ移動して観察範囲を変える。未知の植物や遠隔の実在庫を渡していない。再確認の初期目安24時間は生育時間の学習結果ではない。

採集を選んだ後、到着と同時に市場訪問へ切り替わる反復を防ぐ。実際の植物が残っていれば採集まで目的を続け、枯れていれば新しい観察で見直す。局所の食料を先に取る候補にも、作業後に家へ届く体力の見込みを付ける。帰宅を固定日課にしない。

穀物の売り手は最大6時間、原料を持たない製パン担当は最大3時間の初期待機を区切り、空振り後は24時間後に再検討する。これは待ち時間を経験から最適化する完成版ではない。現物と代金の移転、売り手・買い手の現地、技能と加工条件は世界の規則で検査する。

## 次に進める内容

1. 食料の需要時刻・期限、積み込みの判断間隔、加工と待機まで含む短い行程を比較する。残った積み戻しと食事間隔を対照で測る。
2. 8時間固定の出発時の寒さ予測を、行程と観察可能な昼夜条件へ接続する。Fの見送りが多い理由と、未知の条件を確認する機会を検証する。
3. 実際の売上・空振り・腐敗から、販売待機と製パン・運搬量を更新する。現金の偏在を成功扱いしない。
4. この基盤の後で、既存の[食品経済と技能・職選択の計画](FOOD_ECONOMY_SKILLS_PLAN.md)へ進む。

継続Process中の人格による自律的な再検討は未接続。今回の中断検査は、外部の睡眠中断・行先変更などの結果を対応づける範囲である。初期のランダムな移動先を設定する案も未実装。
