## 2. 現在の荷重と快・不快

[世界の移動法則](../../packages/sim/load-movement.ts)は既に次の値を使う。

```text
歩行速度比 = 10 / (10 + 総重量)
移動の体力消費 / 時間 = 1 + ceil(総重量 / 8)
```

| 総重量 | 歩行速度比 | 移動の体力消費／時間 |
|---:|---:|---:|
| 0 | 100% | 1 |
| 4 | 約71% | 2 |
| 8 | 約56% | 2 |
| 10 | 50% | 3 |
| 16 | 約38% | 3 |

重いほど遅く、時間当たりの消費も増えるので、同じ距離の負担は両方から増える。上表以外に寒さ等の身体消耗がある。穀物だけへの特別罰則ではなく、総重量の法則である。

ただし、不足がある。

- 体力はこれまでの消耗を残す量。持ち上げた瞬間の重さ・圧迫・姿勢による不快とは違う。
- 待機・休憩・作業の荷物を支える状態を区別していない。荷物を置かずに待つ負担や、地面に置いて休む選択がない。
- [快不快表示](../../packages/sim/village-status.ts)は空腹・寒さ・疲労・眠気の最大値を「不快」、`100 - 不快` を「快」とする表示用の代理量。これを動機にして行動を競合させる実装ではない。重さもこの不快へ入らない。
- [判断本体](../../packages/ai/anticipatory-needs.ts)は主に条件分岐の順序と閾値で選ぶ。実行中のProcessには原則として新たな行動を選ばない。

従って「重い物を持つと、現在の不快も増し、次の行動で軽減したくなる」は未実装。移動係数を大きくするだけでは、販売行程の中断・壊れた提示・荷物を置けない問題が残り、帰るための消耗を増やす。

重量・距離・身体の容量にはまだkg・m・代謝量との校正がない。「現在より何倍疲れるべきか」はこの記録だけでは決められない。最初は現行の移動消費を比較基準として保持し、瞬間の負担と荷物を支える状態を追加してから、質量・距離・時間の単位を定めて校正する。

### 追加整理：カロリーの費用と遅れて得られる報酬

ユーザーの追加指摘を[栄養エネルギー・体力・疲労と遅延報酬](ENERGY_EFFORT_AND_DELAYED_REWARD_DESIGN.md)へ具体化した。現行の体力は休息で回復する活動余力で、食事からの代謝供給を持たない。次の身体モデルでは食事で補給する栄養備蓄、休息で回復する活動能力、現在の負担感を分ける。本人は運搬の消耗と、穀物売却→現金→可食物取得までの時刻・成立見込みを一つの行程として評価する。認知的な困難を全て追加のカロリー消費へ換算せず、習熟・注意・不成立の主観的費用も別に扱う。身体と行程評価の詳細は追加文書を優先し、以下の研究・初期人格・提示整合の順序を継承する。

研究からの判断として、**身体的な不足や不快によって行動の価値が変わり、将来の解消のために現在の労力を受け入れる**方式は適している。一方、「どの人間も常に現在の不快を最優先する」「快と不快は必ずすぐ消える」を実証済みの普遍則とは扱わない。本プロジェクトの初期人格では、ユーザー指定に基づいて不快の解消を強く優先する。

感覚は現在の状態から毎回生成する。重さから解放された感覚はすぐ変わるが、荷物を持ったまま時間が経つことを理由に重さの不快をゼロへ減衰させない。疲労や寒さの原因が残れば不快も続く。強い経験は、感覚とは別の記憶として残す。

## 4. 提案：身体・今の感覚・目的を分ける

既存の[小モデルと予測誤差の設計](MODULAR_PREDICTION_AND_ACTION_PLAN.md)を継承する。予測器を選ぶ処理と、その予測を使って行動を選ぶ処理を分ける。

| 層 | 内容 | 変化の例 |
|---|---|---|
| 世界の身体・物理 | 栄養備蓄と活動消耗から求める活動余力、睡眠履歴、冷え、携帯物、支え方、実際の移動・作業 | 穀物を置くと重量が下がる。使った栄養と活動消耗は瞬間回復しない |
| 本人の現在の感覚 | 空腹、寒さ、眠気、活動疲労、重さ・圧迫などの独立した不快 | 荷卸しで重さの不快がすぐ減る。休息で疲労の不快が徐々に減る |
| 快・安堵の体験 | 食事や回復時の一時的な快・安堵 | 不快0を常時最大の快にせず、実際の出来事と経過から扱う |
| 目的・見込み | 次の食事、安定した備蓄、売却代金、約束、解消までの時間と不確かさ | 今重くても、成立見込みのある短い取引なら耐える候補になる |
| 経験記憶 | 状況、予測、実行、感覚の経過、解消・中断・未成立の結果 | 次回は少量を運ぶ、早く出発する、荷卸し、軽装で確認する |

荷物はまず `携帯して支える／地面や収納に支持される` を区別する。バッグ内にあることだけで手持ちか背負いかは決められない。支持先へ置く行動にも、所有・場所・容量・アクセス・所要時間を必要とし、所有物を消したり瞬間移動させたりしない。人格には現在感じた負担と自分の所持品を渡し、物理の将来の消費量そのものを正解として渡さない。

### 行動の選択

1. **危険・実行不能を確認する。** 所有・現物・容量を満たし、移動途中とその後に深刻な身体危険を起こさない候補を作る。強い危険を小さな快や売上点で打ち消さない。
2. **現在の強い不快を軽減する候補を先に比較する。** 置く、収納する、少量にする、休む、食べる、近くの安全な場所へ移る。その場で対処できない場合は、最も早く対処できる経路を候補にする。
3. **我慢に意味があるかを比較する。** 目的、解消までの時間、実在する／未確認の成果、体力と帰路、継続中の不快、不成立時の対処を持つ。「売る職だから」「一度選んだから」だけでは継続しない。
4. **本人が選んだ目的を小さな段階で実行する。** 新しい観察、負担の上昇、現物の変化、待機上限などで再検討する。改善が小さいときには切替の手間を入れ、毎回逆向きに移動しない。

初期には現在の不快を強く重みづけし、身体状態と目的に応じて我慢の限度を持つ。強度の違う不快を単に合計して一律に優先するのではなく、種類ごとの切迫度と最大の負担、軽い負担の重なりを記録する。係数は設計上の仮定として版に保存し、研究が指定した数値とは扱わない。

我慢の比較は、各候補について同じ時刻から同じ予測期間で、現在から解消までの不快の経過を評価する。期間内に終わらない場合の状態と次の食事・睡眠も残す。仮の評価は次を材料にする。

```text
予測した不快の時間積分（近い時間を強く評価）
＋ 深刻な悪化の危険
＋ 実現の不確かさと切替の費用
− 達成可能な将来の必要・約束への寄与
```

将来の快は別の記録・限定した評価項目に置く。金銭は、食品などを得られるという見込みを持つ手段であり、通貨を持つだけで無制限の快が生じる設定にしない。現在置ける荷物を持ち続ける場合には、「置く案より、何の不快をいつ解消できる見込みで我慢したか」をログへ残す。

不快を作ってから解消する繰り返しに利得を与えない。荷物を置く→積むの往復や、空腹をわざと増やす過程も、同じ経過の悪化・継続費用として評価する。体力の安全確認と、主観的な労力・感覚の評価を分け、同じ疲労を無説明に二重加算しない。

### Fの市場行程で必要な候補

- 今の不快を減らして家・畑へ置く。
- 穀物の少量積載・往路 → 提示と限度のある待機 → 売却後の購入と帰路。
- 穀物を運ばず軽装で市場を確認し、実際に得た情報から次の行程を考える。
- 到着した市場の本人所有庫へ売れ残りを収納し、軽くなって帰る。
- 売れない現物を持ち帰る必要があるなら、休憩・帰路を含め、他の案より妥当かを比べる。

市場の本人所有穀物庫は既にある。ただしそこへ保管しただけでは遠隔売却できない。現行の取引は売り手・買い手が市場にいることとバッグ等の現物を要求する。最初は収納で提示を取り下げ、再度現地で取り出して本人が提示する形が整合しやすい。委託販売・雇用を追加する必要はない。

販売提示は荷物の減少でも売上でもない。未確認の買い手を、確定した売却や即時の不快解消として計上しない。帰りに食料の重量が増える場合も含める。

### 経験の更新

身体・時間の予測誤差、取引の成立見込み、行動の価値を分けて更新する。短い候補を予測して選び、本人に届いた実際の区間だけを学ぶ方式から始める。オフラインで全村の記録を学習材料にしたり、ランダム行動を学習の前提にしたりしない。

特に、提示せず避難した経験は「この行程では余裕が足りなかった」材料であり、「その市場に需要がない」という確定材料ではない。提示後の待機を途中で打ち切った場合は、待った時間と中断を保存する。現物不足で実行不能になった提示を、市場の需要低下や人間の我慢不足として学ばせない。予測した消耗が正しかったモデルは保持し、その予測から積む量・支え方・行程を変える。

## 5. 実装の順序と検証条件

| 順 | 実装する内容 | 確認する差 |
|---|---|---|
| 1 | 提示の現物整合と播種ロットの指定。消費・分割・所有移転・消滅で成立不能になる提示を明示的に失効し、本人へ知らせる | 穀物3を提示後に1を使っても、現物2を「購入可能な3」と扱わない。無効な提示で買い手待ちを続けない |
| 2 | 栄養備蓄・活動消耗・活動余力、今の重さの不快、快・安堵を分離。食事・回復と荷物を支持・収納する候補へ接続 | 荷物を置くと直後の不快が減り、使った栄養と消耗は戻らない。食事が供給、休息が能力回復になり、同重量の別物品でも同じ法則を使う |
| 3 | 現在の不快の解消と、目的のための有限の我慢を比較。往路・取引待ち・不成立時の保管／帰路を一緒に予測 | 軽減できる不快を理由なく持続させず、短く成立見込みのある取引は完了できる。単なる職ラベルで運ばない |
| 4 | 実行中の再検討・可能な中断、本人の完了経験による更新、90日の対照比較 | 負担増大・在庫変化・不在・待機期限で見直す。行程の往復、累積不快、食事、所有・通貨・物品保存を測る |

順1の播種では、人格が選んだ具体的な穀物ロットを試行・Processへ渡し、開始と消費時の両方で検証する。既に販売提示したロットを使うなら、先に本人が取り下げる。物理側が別のロットへ無断で置き換えない。数量変更後に世界が価格を自動調整して売ったことにしない。

順4では、現在の `activeAction` 中の早期returnを変え、安全な区切りで中断・荷卸し・休憩・経路変更ができるProcessを用意する。睡眠の身体更新は15分だが、他の移動や作業は今も基本的に時間単位。感覚だけを15分で更新して即時反応を実装したと扱わず、物理進行と判断・中断可能点も合わせる。途中までの移動・消費・作業を保存し、再検討で失わない。

比較は「v20」「提示整合だけ」「感覚と荷卸しを追加」「行程評価を追加」「学習あり／更新なし」と段階を分ける。最初から疲労係数と目的の重みを同時に変更して結果だけ整えることは避ける。古いv19/v20の規則と記録は保ち、新しい規則IDと記録で比較する。睡眠の必要量、食品の生育・腐敗、所有畑、穀物の非可食、薪・雇用停止、本人に届いた情報だけを使う境界は継承する。

最低限の小さい対照は、(a)今置ける荷物、(b)短い販売で荷物と将来の空腹を解消できる、(c)買い手がいない、(d)取引待ちで帰路が危険になる、(e)提示量より現物が減る、(f)身体に余裕があり目的がない、(g)急な悪化で作業を中断する、を含める。売上率を100%にすることは目的にしない。売らない・待つ・帰る理由が、本人の観測と感覚・見込みに対応して説明できることを先に確立する。
