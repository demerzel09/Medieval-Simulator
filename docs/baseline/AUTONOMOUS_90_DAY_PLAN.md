# 自律する90日生活世界への実装計画

更新: 2026-09-27。目標は、**正常条件を与えた小世界で、全員が届いた情報と身体・記憶から判断し、単純な物理法則に対する試行だけで90日生活すること**。90日生存をsimが保証する機能にはしない。旧本編、A3、`individual_life`、`individual_market`、`individual_work`は回帰用に残す。

段階0〜4の版1受入は完了。実行fixtureの初期条件、通常90日と対照の測定は[実行結果](AUTONOMOUS_VILLAGE_RESULT.md)を参照。
版2以降の新しい実装順と受入条件は[土地経済の計画](LAND_ECONOMY_NEXT_PLAN.md)を参照。

## 区切りの定義

最初の基準fixtureはS（商人）、F（食料生産者）、C（運搬人）、B1/B2（買主兼薪などの必要財の供給者）の5人を候補にする。役割は初期技能・場所・持物・習慣・知識で表し、時計やsimが職業名で呼び出さない。全員に空腹・体力・位置・本人所有の財布と食品を持たせる。森、食料資源、家、売場、経路、食品の保存期限を持つ。初期資源量・再生率、作業時間、運搬容量、初期通貨、必要財の消費量について、90日分の物量と時間の実行可能性を事前に計算する。価格と行動は当事者の提示・判断の結果として測る。

正常系の受入は次を**同じ世界・同じランナー**で満たした時点とする。

1. 90日を完走し、5人が各日少なくとも1食を本人の試行で消費する。空腹が累積しない。F/C/SもBと同じ身体・食品ロットの規則を使う。
2. 立ち上がり後も仕事、現物輸送、取引、食事が繰り返される。少なくとも日61〜90にも採集・納品・販売・実物支払が発生し、初期現金や初期在庫を食いつぶしただけの完走ではない。必要財の需要はSの売場営業だけに依存させず、少なくとも一つは別の人物の身体・生活上の必要から生じる。
3. 各試行に本人の判断Eventがあり、判断入力の情報には観察・身体信号・通知の到達根拠がある。注文、在庫、売値、成果を遠方の人物へ直接渡さない。拒否、待機、失敗の後に時計が代役を選ばない。
4. 物体の所在・所有、容量、食品の生産/消費/腐敗、通貨総量、資源の再生/採取、体力消費、仕事の経過時間が整合する。契約は権利の証拠であって食品や通貨を遠隔移動させない。
5. 同一seed・入力Commandの再実行、途中セーブからの再開が同じ状態と因果Eventへ至る。日次の集計と、誰が何を知って選んだかを追えるトレースを出す。通常の確認とは別に、拒否・欠員・資金不足・資源不足・通信遅延を変えた対照で破綻や未遂をそのまま観測する。

日61〜90の継続は、単一の日の取引回数を固定する意図ではない。季節・在庫・判断による休業を許す。正確な回数と初期値は、fixtureの収支表と初回実測を作ってから固定し、失敗を隠す救済として日次給付や強制購入を追加しない。

## 実装順

| 段階 | 実装 | 次へ進む条件 |
|---|---|---|
| 0. 実行可能な基準fixture | 5人の必要食数、採集可能量、移動/作業時間、食料の期限、通貨の巡りと必要財の独立需要を表にする。初期値とルールを版付きで保存する。[版1の数表](AUTONOMOUS_90_DAY_FEASIBILITY.md)と算術検算を作成済み。 | 90日分の潜在供給量・時間が必要量を満たし、通貨の流れに毎日の外部注入を要しない説明ができる。算術上は確認済み。 |
| 1. 共通の起床・情報配送 | `individual_work` の時刻・宛先付き刺激・本人の主観状態を一般化し、`individual_life` の身体判断を同じ人物ループへ載せる。世界Eventからの配達、現地観察、身体信号を区別する。 | 2人の依頼、3人の採集生活が同じランナーで動き、未到達情報の利用・二重配達・拒否後の代行を対照で防ぐ。 |
| 2. 単純な物理sim | `physical.ts` の物体木を正本として、場所/道、容量と荷重、時間のかかる移動・採集・荷役、体力・休息、空腹・食事、資源再生、食品腐敗を局所法則にする。行動中の進捗を保存する。 | 出発前・道中・到着後の物と人物の位置が一致し、時間/体力/物量の保存、途中セーブ、同時刻競合が小fixtureで通る。 |
| 3. 本人間の取引を接続 | Sの提示、Cへの依頼・承諾、Fの採集と現地引渡し、Cの実物輸送、Sの陳列、B/F/C/Sの買物・食事を、全員の起床と試行だけでつなぐ。契約証拠の範囲から一時権限を検証する。 | 連続する複数取引で、拒否・部分納品・不足金・契約外の支払が正しく拒否/部分成立し、職業別phaseなしで3〜7日進む。 |
| 4. 独立需要と90日調整 | Bの薪供給に加え、Sの売場以外の人物が生活上必要とする薪または他の単純な必要財を入れる。全員の所得・支出・自家消費を測り、本人の判断則と初期条件を調整する。 | 上の90日受入と対照実験が通る。基準fixture以外の結果を同じ成功と称さず、どの条件で破綻するか記録する。 |

単純な物理simの範囲は、この5人の生活を成立/失敗させるための局所法則に限る。距離と荷重による所要時間・体力、食品と通貨の現物、資源再生、腐敗、身体の必要までを先に実装する。馬車、水車、天候、疾病、複数食品、詳細な栄養、政治・戦争、大規模人口はこの区切りの必須条件にしない。最小の `ActionProcess` は時間のかかる移動・採集・荷役を保存できる形とし、動力や負荷の一般式は[設計案](../foundations/ACTION_PROCESS_DESIGN.md)と整合する方向で後から広げる。

## 実装上の境界と記録

`PersonalityModel` が試行と次回起床を返す。時計/配送は届く刺激と進行時刻を決める。世界Gatewayは現在の位置、資産、権利、体力、作業中かを検証し、受理・拒否・完了をEventにする。本人の記憶は世界の結果から自動変更せず、刺激が届いた後の本人の応答で更新する。商談や契約を世界が「成功させる」処理は作らない。

各段階で保存形式を明示し、旧モードを暗黙移行せず回帰テストで守る。新モードには日別の食事/空腹、資源、所有別の食料と通貨、仕事の受諾/進捗/納品/支払、届いた刺激、未完の仕事、拒否理由を出すCLIを作る。90日基準と対照の結果、実行時間、未達条件を[STATUS](../STATUS.md)へ更新する。
