# 栄養不足：可食物の供給不足と取得・摂食の問題を分ける

更新: 2026-10-03。ユーザー指定により、[v22の栄養枯渇](ENERGY_EFFORT_V22_RESULT.md)を「食料取得の判断が悪い」と一括して扱わない。[監査JSON](../../artifacts/v22-food-availability-audit.json)は既存の90日記録の最初の240時間を、保存した判断と応答で再実行した結果である。全Eventの接頭部分と判断入力の一致を確認した。身体・食品・判断の規則と同梱記録は変更していない。

## 評価の原則

食料から活動に必要なエネルギーを得ることを、生活・生産・取引の中心的な課題として扱う。生育待ち、労働と運搬の消耗、加工、所有権、資金、本人の情報と判断によって栄養不足が起きる場合、その因果を追えることにはシミュレーターとして価値がある。不足に至った経過と結果を保存する。

因果の説明に加え、栄養・物品・貨幣の収支、所有権、身体と生育の規則が整合し、同じ初期条件から再現できることを確認する。帳簿の破綻、取得・摂食できる食品の実装上の見落とし、根拠のない身体・生育係数には修正・検証の必要がある。現行の栄養単位は未校正であり、今回の結果を中世の実際の飢餓の再現と評価する段階にはない。

90日の生活継続は、資源・生産・加工・取引の条件と本人の適応がどう組み合わさるかを測る実験目標とする。正常系の生活継続が未達であること、不足条件で整合した結果が出ること、実装の不整合があることを、それぞれ記録する。需要に応じた技能・職の切替で生活を持続させる後続目標も維持する。

## 判定の順序

「世界に食品が存在する」「本人が取得できる」「必要な期間を賄える」を別々に確認する。

| 確認 | 分けるもの | 対応 |
|---|---|---|
| 摂取と吸収 | 未摂食、吸収待ち、吸収済み、容量超過の損失 | 2時間の吸収待ちを摂食の失敗に数えない。栄養帳簿の不整合なら身体実装を直す |
| 本人の可食物 | 携帯、現地で取り出せる自分の保管品、遠方の保管品 | 取り出せる食品を持ち、食べる必要もあるのに食べない場合は、作業中・睡眠中等の理由を調べて判断を調整する |
| 現在の可食供給 | 成熟した採集対象、保管済みの食品、再生待ち、未加工穀物 | 未加工穀物や成熟前の植物を、今すぐ食べられる供給へ加算しない |
| 取得条件 | 発見、採集競合、経路、身体余力、所有権、価格、容量、実際の販売提示 | 食品があっても、その人物が取得できるとは限らない。取得できた具体的な行程を検証してから判断の失敗とする |
| 期間全体の供給 | 生育周期、加工・取引、必要量、労働消費、腐敗、供給の空白 | 在庫の一時点の合計だけで「十分」としない。可食物への変換が止まる場合と、生産資源自体が不足する場合も分ける |

不足の結果として栄養備蓄がゼロになった後、食品が再生しても取得できない場合がある。後の食品の存在だけから、先行する供給不足を否定しない。本人の感覚・観察・記憶と、監査者が見られる世界の実量も混ぜない。

## v22の最初の10日で確認した事実

### 手元に食品があるのに食べない状態か

備蓄Nが供給閾値12単位未満の判断で、携帯または現地の自己保管品から可食物を取り出せる場面は合計9回。Sが2回、Fが2回、Cが1回、B1が1回、B2が3回で、**全て実際に`eat`を選んだ**。Nがゼロの判断では、取り出せる自己の可食物と吸収待ちは全員0件だった。

この窓では「自己の食品を持ちながら食べずに枯渇する」不具合は確認できない。この結果を90日全体や別seedへ一般化しない。

### 可食物が存在しない時間帯

各時間の最初の人物判断直前に、成熟して採れる野生食品と物品として保管された可食物が両方ゼロだった時間末は42回。

| 世界hourの範囲 | 時間末の観察回数 |
|---|---:|
| 97〜103 | 7 |
| 139〜154 | 16 |
| 164〜182 | 19 |

これは現在の可食供給が途絶えた観察であり、将来の再生や人物の体内備蓄が全てゼロという意味ではない。再生待ちの株に残る数量や、野草1単位の端数は、現行規則で採集・食事できないため含めない。

hour145には**未加工穀物107単位**が保管されている。所有はF43・B1は21・B2は43、S/Cは0。成熟した未収穫穀物も20単位ある。しかし保管済みの可食物と成熟した野生食品はゼロだった。したがって、この時間帯を「土地の生産資源そのものがない」とは判定しない。**穀物を可食物へつなぐ加工・取引が停滞し、野生食品の再生待ちと重なった可食供給の不足**である。穀物を直接食べる救済は入れない。

### 枯渇時点での違い

以下のhourはNがゼロになっていた最初の保存判断。栄養量はゲームの仮の単位で、実人体のkcalではない。

| 人物 | hour | 成熟した野生食品 | 保管済みの可食物 | 本人の取得条件 |
|---|---:|---|---|---|
| B1 | 156 | 野草2地点、合計48栄養単位 | なし | どちらも現在の視野外。1地点はCが採集中。活動余力は0 |
| C | 179 | なし | なし | 現在の可食供給自体がゼロ。未加工穀物107は別に存在する |
| F | 189 | ベリー1地点、120栄養単位 | S/B2のベリー、計72栄養単位 | ベリーは見えているが活動余力0。自己の食品・吸収待ち・購入可能な提示はない |

Fのhour187はN1.5程度で、ベリーへ移動を始める。188には余力不足で途中に止まり、189にはNがゼロになる。C/B1も、可食供給の空白期間に未成熟地点間の探索を繰り返して消耗していた。食品が後から再生しても、Nゼロでは移動・採集の身体制約を満たせない。単に休むだけでは栄養は戻らない。

Fの世界全体の食品192単位を、そのままFが使える在庫とは数えない。他人の食品には所有権があり、野生食品には移動・採集・吸収までの費用と時間がある。この時点の食料の存在は、Fが栄養を回復できる行程の証拠ではない。

## 調整の順序

1. **可食供給の成立を測る。** 穀物の所有・運搬・有効提示・製パン・販売・食事と、植物の採集可能量・再生時刻を時系列で追う。必要な食料が生産できない対照では不足を正常な結果として残す。原料があるのに変換が止まる場合は加工・取引の制約と判断を調べる。
2. **枯渇する前の食料行程を検証する。** 観察済みの可食物について、到達だけでなく採集・食事・吸収までの消耗を確認する。現在のv22は移動開始の余力確認だけでは、到着後に採集する余力を保証できない。別人が先に採集する場合も分ける。
3. **再生待ちの探索を評価する。** 食品のない既訪問地点を毎時間巡る行動と、本人の記憶に基づく再観察・新しい場所の探索・待機を比較する。待てば必ず食料が得られるとは仮定せず、再生の見込みと実結果を対応させる。世界の未来の植物状態を本人へ渡さない。
4. **原因ごとの対照を保持する。** 食品があり取得可能／食品はあるが遠い・競合・他人所有／食品が未加工／可食供給がない、を別条件として比較する。取得できる食品を見逃すと確認できた場合に判断を修正する。生育周期・身体消費・睡眠必要量の調整は、それぞれの根拠を示した独立の変更にする。

この監査だけから、全員を養える供給が期間全体で十分とも、身体係数が不適切とも断定しない。特に、植物を部分収穫しても株全体を再生待ちにする現行設定は、有効供給量を小さくする条件として別途測る。供給不足と判断の失敗が併存する場合は両方を報告する。

## 再実行と検証

```bash
PATH="$HOME/.local/node/bin:$PATH" node_modules/.bin/tsx packages/tools/village-food-audit.ts \
  fixtures/recordings/autonomous-village-energy-effort-90.v2.json.gz \
  --until-hour 240 --output artifacts/v22-food-availability-audit.json
```

既定窓は最初の240時間。`--until-hour`で保存記録内の別の終了時刻まで検査できる。低栄養（N<12）、枯渇（N=0）、吸収待ち、現在の可食物の有無、本人の保管品、観察、採集競合、経路、開始時の余力を別の項目に出す。余力の欄は最短経路と最小1食の作業量を開始時に比較する簡易値で、途中の回復・吸収を含む行程の成否は判定しない。全世界の可食量と本人の判断を照合するための読取監査で、人格の入力には追加しない。
