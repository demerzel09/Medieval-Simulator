## 現在地と数量上の制約

版2の通常90日は5人が計450食を消費するが、その食料は日次再生する野生ベリーに依存する。畑の穀物は4日程度の `cultivation` 対照で、耕作・播種・72時間の成長・収穫を確認した段階にある。1区画の収穫は5食なので、成長時間だけを数えても90日で最大150食程度であり、450食に届かない。3区画は成長時間だけから見た下限で、立ち上がり、耕作・播種・収穫、移動、種、腐敗、不作を含めると余裕が必要になる。必要区画数をこの算術だけで確定しない。

## 実装順と受入条件

| 順 | 作業 | 次へ進む条件 |
|---|---|---|
| 1. 90日の土地収支を確定 | 5人の450食に対し、区画数、収量、初期種、成長と作業時間、Fの移動・体力・自家消費、Cの運搬量、保存期限、通貨循環を日別に試算する。果実・野草を補助食に使う場合も供給元と量を分ける。旧ベリーの自動再生だけで成立する条件を新正常fixtureの根拠にしない。 | 供給量と労働時間に余裕のある候補fixtureを版付きで残し、不足する条件も数表で説明できる。現行1区画・種不足・移動増の対照を定義する。 |
| 2. 栽培と取引を一つのランナーへ接続 | 複数区画と作物ごとの育て方をFの現地観察・技能・所持種による試行に載せる。収穫食品を所有者と産地が追えるロットにし、Sの提示、Cの現地引渡し・運搬、販売、5人の食事までつなぐ。場所が変わる注文・待合せは到達した情報と実際の位置で処理する。 | 小fixtureの3〜7日で、播種から食事まで因果を追える。遠隔作業、技能・種・土地利用権・容量不足、未到達の依頼は拒否される。途中保存と記録再実行が一致し、食品・種・通貨が検算できる。 |
| 3. 土地に支えられた正常90日 | 順1の条件を固定し、栽培食品を主食として5人の独立判断で90日進める。野生の果実・野草は場所・再生量に従う補助供給とし、食品ロットの産地別に採集、販売、食事を集計する。 | 全員が各日食べ、日61〜90にも栽培・収穫・取引・食事が発生する。栽培食品が日61〜90の消費食数の過半を占め、旧版の野生ベリー日次供給だけでは成立しない。通貨・食品・種・植物パッチを検算し、同じ記録の再実行と途中再開が一致する。 |
| 4. 対照と拡張 | 区画/種不足、不作、道路閉鎖、作業者の拒否・技能不足、通信遅延を別記録にして正常系と最初の差分・日別結果を比較する。その後、果樹・野草の固有の育成過程、季節、動物の繁殖・死亡、複数人の道利用を必要な局所法則から増やす。 | 不足や遅延が行動・物量・結果に反映され、世界が日次給付や代理作業で補わない。追加した法則ごとに保存・再実行と物量の検算を維持する。 |

各段階の人格は `PersonalityModel` の境界を維持する。世界は時刻、情報到達、土地・身体・物体の局所変化、試行の権限と結果だけを確定する。耕作や買物を職業別の日課として実行しない。土地の所有・利用権と、収穫物の所有を分ける。経路は版2のA*を基礎とし、通行止め・行き先変更の途中状態を記録する。

順3の「過半」はこの計画の新正常fixtureの受入線であり、版2の成功判定を遡って変更しない。果樹・野草・動物を含む一般的な生態系や、人格・人口・地理を変えた一般性は順4以降の対照で検証する。各段階で[実装状態](../STATUS.md)に実測と未達を追記する。
