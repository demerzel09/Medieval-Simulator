# 睡眠・眠気・活動疲労の身体モデル

更新: 2026-10-03。ユーザーの「24時間に6時間の睡眠」「夜22:00〜6:00は眠く、昼は目覚めやすい」「十分眠った後の18時間は覚醒の長さだけで眠くならない」「強い活動疲労でも眠くなる」という条件を具体化した設計。v20で身体・Process・本人の予測・保存・表示へ実装した。[実装と検証](SLEEP_REGULATION_V20_RESULT.md)にコード対応と実測を記載する。

本書を睡眠・疲労の数値設計の正本とし、[身体と行動選択](NEEDS_AND_ACTION_SELECTION_PLAN.md)・[本人の予測と学習](MODULAR_PREDICTION_AND_ACTION_PLAN.md)へ接続する。6時間はこのシミュレーションの初期設定。人間一般の必要睡眠時間を6時間と断定するものではない。

v20以後の身体拡張は[栄養エネルギー・体力・疲労と遅延報酬](ENERGY_EFFORT_AND_DELAYED_REWARD_DESIGN.md)で設計し、[v22](ENERGY_EFFORT_V22_RESULT.md)で食事からの供給・活動疲労・休息の回復を分離した。本書の体力と`F = 1 - energy / maxEnergy`は比較用v20の仕様であり、kcalの残量や独立した疲労状態ではない。睡眠圧・必要睡眠・昼夜リズムはv22でも継承する。

## 1. 比較基準v19の問題

[旧規則の身体更新](../../packages/sim/needs-body.ts)は覚醒中に `sleepDebt += 1`、睡眠中に屋内なら `−2`、屋外なら `−1` を毎時適用する。値は0〜48に制限され、休憩では減らない。

- 十分眠った直後でも、起きて1時間経つと「睡眠不足1時間」となる。覚醒の経過と、不足している睡眠量が混ざっている。
- 屋内で6時間眠り18時間起きると、制限に達していない範囲では `18 − 2×6 = +6`。24時間の増減を釣り合わせるには8時間睡眠が必要になる。
- 眠気の表示は `sleepDebt / 24`。昼夜の覚醒しやすさや活動疲労から独立した眠気はない。
- [睡眠Process](../../packages/sim/autonomous-world.ts)は固定8時間。寝ようとする時間と実際に眠った時間を分けず、自然な目覚めもない。`wake_up` はv19では外部commandからの中断である。
- [予防判断](../../packages/ai/anticipatory-needs.ts)や[食品行程](../../packages/ai/food-planning.ts)も `sleepDebt + 行程時間` と閾値20/24を使う。身体だけを直すと、本人の見込みと物理法則が食い違う。

現行の `sleepDebt` は旧規則の覚醒負担として残す。新規則の睡眠不足時間への読み替えや、旧記録の結果の上書きは行わない。

## 2. 分けて持つ量

| 量 | 意味・単位 | 更新・表示 |
| --- | --- | --- |
| 直近24時間の睡眠量 | 実睡眠と、その回復の質から求める時間 | 時刻付きの履歴から求める。寝ようとしている時間は含めない |
| 睡眠不足 `sleepDeficit24` | 必要な6時間に対する直近24時間の不足、0〜6時間 | 身体欄は「睡眠不足 ○時間」。目覚めたことを理由に加算しない |
| 睡眠圧 `S` | 覚醒で増え、実睡眠で減る内部の回復要求、0〜1 | 短い昼寝で一律0に戻さない。通常画面には別の不足として表示しない |
| 連続覚醒時間 | 最後に実睡眠から目覚めてからの時間 | 補助情報。睡眠圧へ再び加算して二重に数えない |
| 昼夜リズム `C` | 時間帯による睡眠・覚醒のしやすさ、0〜1 | 初版は22:00〜6:00を夜として固定。家へ帰る命令にはしない |
| 活動疲労 `F` | 現行の体力から求める消耗度、0〜1 | 移動・荷重・作業で増え、休憩と睡眠で回復する |
| 眠気 `L` | 睡眠圧・不足・昼夜・強い疲労を合成した現在の身体信号、0〜1 | 身体欄は「眠気 ○%」。睡眠不足時間の単なる換算をやめる |

「18時間は眠くない」は、十分な睡眠後に**覚醒の長さによる眠気の寄与が18時間まで0**という条件とする。夜、以前からの睡眠不足、強い疲労による眠気はその期間にも起こる。すべての条件で18時間の完全な覚醒を保証すると、他の要求と矛盾する。

## 3. 参考理論と採用範囲

Borbélyの二過程モデルは、睡眠・覚醒に応じて変わる恒常性の過程Sと、概日リズムの過程Cを分け、相互作用で睡眠を説明する。本書はこの分離と睡眠中の指数的な回復を参考にする。[著者による解説（2022）](https://pubmed.ncbi.nlm.nih.gov/35502706/)、[再検討（2016）](https://pubmed.ncbi.nlm.nih.gov/26762182/)。

以下の係数、24時間の不足量、活動疲労との合成、入眠・起床条件は、このゲーム用に定める近似である。論文のモデルを完全再現した実装や、OSSの睡眠エンジンの導入ではない。現行のTypeScriptの身体モジュールへ小さな計算として実装できる。

6時間を普遍的な生理定数にはしない。6時間などの睡眠制限を継続した実験では累積的な認知成績の低下が報告されている。[Van Dongenら（2003）](https://pubmed.ncbi.nlm.nih.gov/12683469/)。本書の初版は依頼された6時間を成立条件とし、長期の認知機能、睡眠段階、年齢差、疾病、個人差の再現は対象外とする。

## 4. 睡眠量と不足時間

時刻 `t`、必要量 `R = 6時間`、窓 `W = 24時間` とする。

```text
effectiveSleep24(t) = ∫[t−24h, t) asleep(u) × quality(u) du
sleepDeficit24(t)   = max(0, R − effectiveSleep24(t))
```

`asleep` は実睡眠なら1、それ以外なら0。`quality` は0〜1の回復の質。初期の温暖で静かな条件では1とし、実睡眠6時間を6時間として数える。昼寝も実際に眠った分を加算する。冷えや中断で回復が悪ければ、同じ実睡眠時間でも有効量は少なくなる。

- 日付が変わっても履歴をリセットしない。窓と重なる区間だけを積算する。
- 睡眠6時間と覚醒18時間の周期なら、どの時点の24時間窓にも睡眠が6時間あり、不足0を維持する。
- 十分眠った直後と、通常の18時間覚醒までに不足を作らない。18時間を超えると過去の睡眠が窓から出始め、20時間覚醒で不足2時間、24時間覚醒で不足6時間になる。
- 眠った6時間を過ぎて眠れば、その期間の回復には使えるが、未来の何日分もの睡眠を備蓄したことにはしない。
- 不足を毎時さらに累積加算しない。直近24時間の不足は派生値で、長期の累積負債とは別である。初版は慢性的な認知低下の独立モデルを持たない。

履歴には実際の開始・終了時刻と質を持たせる。15分の固定身体区間を使えば直近24時間は96区間で保持できる。欠けた開始前の履歴を「睡眠0時間」として埋めない。

## 5. 睡眠圧Sと短い昼寝

覚醒中と実睡眠中で、次の式を適用する。`Δt` は実際に経過した時間。

```text
覚醒中： S' = 1 − (1 − S) × exp(−Δt / τWake)
実睡眠： S' = S × exp(−quality × Δt / τSleep)
```

初期値は `τWake = 18時間`、`τSleep = 3時間`。係数は初期設定であり、身体経験を学習する人格側の係数とは別に保存する。

6時間睡眠・18時間覚醒の安定周期から、睡眠直後の `SRested` と18時間後の `S18` を求める。

```text
a = exp(−18 / τWake)
b = exp(−6  / τSleep)
SRested = b × (1 − a) / (1 − a × b) ≈ 0.090031
S18 = 1 − (1 − SRested) × a         ≈ 0.665241
awakeDrive = clamp((S − S18) / (1 − S18), 0, 1)
```

睡眠圧自体は覚醒直後から少しずつ増えるが、それを「睡眠不足○時間」と呼ばない。通常周期の18時間まで、覚醒由来の眠気 `awakeDrive` は0になる。睡眠が不十分なら開始時のSが高く、18時間より前にこの寄与が出てもよい。

18時間覚醒後のSは約0.6652。そこから1時間眠ると約0.4767、4時間なら約0.1754、6時間なら約0.0900になる。1時間の昼寝で連続覚醒時間が区切られても、Sを十分寝た値へ置き換えない。休憩や待機ではSは覚醒の式で進める。

## 6. 昼夜のリズムC

身体の環境時刻から夜の係数 `C(t)` を求める。温度とは別に扱い、暖かい夜にも眠気の傾向を残す。

| 時間帯 | 初版のC |
| --- | --- |
| 6:00〜22:00 | 0。昼の覚醒を支える |
| 22:00〜23:00 | 0から1へ滑らかに増加 |
| 23:00〜5:00 | 1。夜の睡眠傾向が強い |
| 5:00〜6:00 | 1から0へ滑らかに減少 |

移行には `smoothstep(x) = x²(3−2x)` を使う。22:00や6:00の境界で急に眠気が跳ねないようにする。初版の位相・窓は身体モデル版1の固定係数とし、fixtureにモデル版を保存する。必要量・Sの時定数・開始前履歴はfixtureに保存する。将来の照明、日の長さ、生活による位相変化は後続であり、初版は実装しない。

夜の寄与はSに応じて弱める。十分寝た直後に、夜というだけでまた寝直す身体にしない。

```text
nightDrive = C(t) × clamp(S / S18, 0, 1)
```

世界が「22時なので家へ帰れ」と命令しない。夜は眠くなりやすく、昼は入眠しにくく目覚めやすい条件を作る。寝る場所と時刻は、本人の欲求・仕事・備蓄・既知の場所から決まる。

## 7. 活動疲労と眠気

初版の活動疲労は、現行の体力を使う代理量とする。

```text
F = clamp(1 − energy / maxEnergy, 0, 1)
fatigueDrive = clamp((F − 0.65) / 0.35, 0, 1)
deficitDrive = clamp(sleepDeficit24 / R, 0, 1)
L = clamp(max(awakeDrive, deficitDrive)
          + 0.45 × nightDrive
          + 0.60 × fatigueDrive, 0, 1)
```

Sと直近の睡眠不足は関連するため、初版では両者の最大を使い、同じ不足を単純加算しない。活動疲労は65%を超えてから眠気へ寄与し、ひどく消耗すれば昼でも眠くなる。これらの重み・閾値は仮の身体係数で、実測で比較する。本人の好き嫌いや学習済みの行動価値ではない。

体力の扱いは次のようにそろえる。

- 移動・荷重・作業の費用は現在のProcessで一度だけ差し引く。身体更新でも同じ作業費を引かない。
- 温暖な休憩は現行の `+2体力/時間` を初期値として維持する。Sや睡眠量は回復しない。
- 実睡眠中は `+2 × quality 体力/時間` を初期値とする。実経過分だけ回復し、Process完了時にさらに加算しない。
- 屋内／屋外の名前だけで睡眠回復を2倍／半分にしない。まず現在の冷えで質が変わる。初期候補は `quality = clamp(1 − 0.5 × cold / 12, 0.5, 1)`。温暖な屋外なら屋内と同じ回復も可能にする。
- 寒さの体力消耗は現行の身体側で一度適用する。強い寒さによる中断があれば、その後は実睡眠の量と回復を加算しない。

栄養不足や筋肉損傷をすべてこのFで説明したとはしない。後続で必要になれば活動疲労と栄養・損傷を分ける。

ユーザーの追加指定により、次は[栄養と活動能力の分離](ENERGY_EFFORT_AND_DELAYED_REWARD_DESIGN.md)を進める。新規則の眠気へ使う強い活動疲労は独立した活動消耗から求め、栄養不足で活動余力が下がった分を全て眠気へ読み替えない。休息は栄養を生成せず、食事も睡眠不足を瞬間解消しない。現行v20の数値・記録はそのまま比較基準として残す。

## 8. 入眠・睡眠維持・目覚め

身体の状態を `awake → settling → asleep → awake` とする。`sleep` 試行は「寝ようとする」を開始し、即時に実睡眠とはしない。

| 状態・遷移 | 初版の条件・結果 |
| --- | --- |
| 寝ようとする | 権利上利用可能な場所で、現在のProcessと両立できる場合に受理。`settling` 中は覚醒として計算する |
| 入眠 | `L ≥ 0.55 − 0.20×C` が15分続けば `asleep`。夜は入眠しやすく、昼でも強い不足・疲労なら眠れる |
| 入眠できない | 試行開始から2時間たっても入眠しなければ終了し、実睡眠0・入眠不成立を結果として届ける。静かな休息の体力回復は経過分だけ適用する |
| 睡眠中 | 実睡眠・質・S・体力を経過時間分更新。入眠の閾値を下回るたびに即座に起こさない |
| 自然な目覚め | 実睡眠が30分以上続き、`S ≤ SRested`（固定精度の丸め誤差を許容）、不足0で、`L ≤ 0.10 + 0.15×(1−C)`。昼は目覚めやすく、夜は睡眠を維持しやすい |
| 本人の起床 | 入眠前に本人が選んだ起床予約、または身体・環境の刺激で再検討可能になったときの `wake_up` を受理する。自然起床の条件が満たされなくても起きられる。熟睡中に毎刻み仕事を再評価する人格にはしない |
| 身体・環境による中断 | 強い冷え、利用不能となった場所、将来の騒音等。初版の冷え中断候補は `cold ≥ 12`。理由と実睡眠分を残し、完了した十分な睡眠とは学習しない |

前日の睡眠がまだ24時間窓に残っている間は、不足0だけで十分回復したとはいえない。自然起床には通常周期の睡眠圧までの回復も必要とする。初期不足fixtureの高いSを、回復後の閾値として使わない。

入眠と起床の閾値を分け、1刻みごとの睡眠／覚醒往復を防ぐ。30分の維持条件は身体上の平常な自然起床だけに適用し、命令や危険からの中断を妨げない。

不足0でも、夜の傾向や強い活動疲労で眠り続ける場合はある。朝6時というだけで不足の大きい人を強制的に起こさない。本人が起きた場合は、その不足と体力をそのまま引き継ぐ。自然な目覚めは世界の身体遷移で、帰宅や働く職の指定ではない。

固定8時間のProcessは新規則ではやめる。本人の予定睡眠時間と、実際の入眠待ち・実睡眠時間・自然起床・中断を別に記録する。AIの呼び出しを予約する現行の `nextWakeAt` / `wakeActors` と、身体の目覚めは別の機能として扱う。

## 9. 時間・初期状態・記録

### 時間

身体は固定15分区間で更新する。世界の1時間の更新内で4区間を順に進め、入眠・起床が区間途中で起きたときも、実際にその状態だった区間だけを計算する。行動判断が初版では1時間単位なら、目覚め後から次の判断までは覚醒待機になる。自然起床時刻と次に行動を決めた時刻を同じ値に潰さない。

各区間の行動・回復・寒さの費用を適用した後の体力でFとLを求める。他のProcessの費用を初版では1時間境界で適用する場合も、その費用の適用後に派生する身体信号を再計算し、同じ時刻のEvent・観測とそろえる。開始境界で受理した睡眠を直前の1時間へ遡って加算しない。自然起床でProcessが終了した場合、その後の区間を睡眠として進めない。

5/15/30/60分の画面再生刻みは表示設定であり、身体の法則を変えない。世界時刻・身体区間・履歴の端点を一つの時刻軸へ統一し、暦日の境界、気温計算、行動ログと照合する。区間は `[開始, 終了)` で定義し、開始時刻の0時間は睡眠として加算しない。

### 初期状態

不足0とだけ指定して履歴を空にすると、初回更新で不足6時間になる。新fixtureは次を明示する。

| 初期条件 | 指定する履歴と状態 |
| --- | --- |
| 十分寝た覚醒状態 | 開始直前の6時間の実睡眠、質1、Sは約0.090031、連続覚醒0、不足0 |
| 睡眠途中 | 開始前の実睡眠、開始前の覚醒から求めたS、Processの実際の開始時刻・状態。残りの予定分はまだ回復させない |
| 初期から不足あり | 直近24時間の不足を生む実履歴と、それ以前からのSをfixtureへ明示。不足の数値だけを初期化しない |

開始前の履歴は初期条件として記録し、本人がゲーム中に獲得した経験回数へ加算しない。現行の世界開始時刻は維持できる。昼夜による夜の眠気と、十分寝た初期状態を独立に計算するため、時刻に合わせて架空の睡眠を追加しない。身体対照では6時直後などの時刻も明示して比較する。

### 保存・Event・画面

- 保存する身体状態はモデル版、S、直近24時間の区間履歴、睡眠状態、実睡眠開始・起床時刻、実経過、体力とする。世界の保存境界は1時間ごとで、固定15分更新の途中で保存する入口は設けない。履歴と状態は15分の端点を維持する。
- Sは固定精度（初期候補は100万分率の整数）、有効睡眠は固定精度の分で保持する。丸め位置と係数をモデル版に固定し、保存再開と同じ刻みの再実行を照合する。
- `sleep_attempted`、`sleep_started`、`sleep_woke`、`sleep_interrupted`、入眠不成立と `body_changed` を区別し、原因の判断・Process・場所へつなぐ。
- 実睡眠の結果には実睡眠時間、有効量、入眠待ち、体力変化、眠気変化、起床理由を残す。15分ごとの詳細は監査用に保存し、通常の行動ログは開始・終了・強い変化を中心にする。
- 身体欄では「睡眠不足 ○時間」「眠気 ○%」を表示する。必要なら直近24時間の睡眠実績・連続覚醒時間を詳細で確認する。Sは通常の不足表示として増やさない。
- v20の保存・記録は `village-shared-state-v1` の外包で同じJSON部分を共有する。復号後の世界・記録のschemaは2を維持し、可変の世界は参照を独立に復元する。大きい世界のハッシュは同じJSON順序の分割計算で求める。旧記録のファイルを変換しない。
- 旧記録の `sleepDebt` と `sleepDebt/24` は旧方式として読み、新記録の眠気と同じ尺度だと説明しない。

## 10. 本人の予測と学習への接続

世界は現在の身体信号を届ける。本人は現在の眠気・不足・体力、自分が知った入眠・起床時刻と回復経験、既知の場所・所要時間を使う。他人の履歴や、目的地の未来の睡眠の質を渡さない。世界のSの内部状態と物理係数を、未来の正解つきの予測器として人格へ渡さない。

本人の小モデルは次を分ける。

| 小モデル | 観測・経験 | 予測する内容 |
| --- | --- | --- |
| 覚醒中の眠気 | 自分の睡眠・覚醒履歴、時刻、現在の眠気 | 作業・移動を続けた場合の眠気。初期の近似と本人の経験モデルを比較する |
| 昼夜リズム | 時刻ごとの眠気・入眠結果 | 夜の眠気、昼の入眠しにくさと起床の傾向 |
| 場所での回復 | 入眠待ち、実睡眠、冷え、体力・眠気の結果 | 眠れるまでの時間、実睡眠による回復、途中で起きる可能性 |
| 活動疲労 | 行動・重量・体力変化と眠気 | 移動・作業の消耗と、それによる眠気 |

予測は現在値だけでなく、到着・作業完了・帰路・入眠待ち・睡眠中の時間帯を順に進めて比較する。6時間後に夜になる条件は、昼の係数で6時間分の不足を足す計算にしない。本人の履歴推定では、過去の睡眠が24時間窓から出ることも予測する。

`必要量 − 現在の24時間睡眠量` を一度計算して、それだけ寝ればよいとも扱わない。寝ている間に以前の睡眠が窓から出るため、現在の不足0でも次の睡眠が必要になる。本人は候補の経過を模擬して、予想する起床時の不足・眠気・体力と所要時間を評価する。

経験との対応では、入眠待ちと実睡眠、自然起床と中断、寒い区間と温暖な区間を区別する。実睡眠の予定時間を回復実績として数えない。「不足が0のまま」を回復率0の証拠にしない。24時間窓からの履歴の退出や、上下限で制限された値を単純な回復速度へ割り当てない。Sの0近辺での結果も、観察可能な眠気・体力・実睡眠の変化で評価する。

現行の閾値20/24、屋内2／屋外1の不足回復率、固定8時間睡眠、`debt + hours` は新しい規則で使わない。食品行程は予想する途中・到着時の眠気、疲労、入眠できる時刻、帰宅／現地睡眠の費用へ置き換える。体力モデルの `debt20/debt24` の条件キーも新しい眠気の観測へ版を切り替える。旧モデルの経験は異なる意味の値へ転用しない。
