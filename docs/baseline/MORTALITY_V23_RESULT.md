## 現在は、何を条件に切り替えるか

実装は[effortDecision](../../packages/ai/effort-choice.ts)。全行動を同じ比較表に並べる方式ではなく、条件を上から判定して最初に選べた行動を返す。売却行程の比較は、主に穀物を何単位積むかの比較である。

| 優先する条件 | 現行の行動 |
|---|---|
| 作業中／睡眠中 | 身体・期限に応じ継続、中断、起床を判断 |
| 空腹で食べられる手持ちあり | 食事。穀物は対象外。吸収には2時間必要 |
| 可食の手持ち2食未満で、その場で取得可能な自分の食品あり | 地面／自宅から取り出す。市場では実在する購入可能な提示を買う |
| 荷重、眠気、寒さ、活動疲労が大きい | 荷卸し、睡眠、避難、休憩。活動疲労0.55以上の回復は売却開始より先 |
| 既に有限の売却目的があり、穀物を携帯中 | 期限内なら市場へ向かう。現地で提示、待機、撤回を判断 |
| 可食の手持ち2食未満 | 現地採集、見える植物、覚えた植物、採集地点の探索を先に選ぶ |
| 上記で行動を返さず、所有する現地の穀物庫に播種留保を超える余剰あり | 所持金8未満、再試行時刻到達、農作業目的なし、食品持参ありなら積載量を比較して売却目的を作る |
| 別地点の所有畑に余剰あり | 食品2食以上、所持金8未満、再試行時刻到達、農作業目的なし、8〜13時、活動疲労0.35未満、往復の寒さ見込みに余裕ありなら穀物庫を訪ねる |

売却候補は1〜5単位、最初のロット数量・播種留保4単位・携帯容量で制限する。往路の荷重、最長2時間の提示待ち、購入時間2時間、売れなかった場合の荷重付き帰路を見込む。疲労見込み0.92未満、寒さ8未満、眠気0.88未満、食品持参を成立条件とし、本人の成功／未成立経験による販売確率と、現金を得る便益・負担から正の評価の候補を選ぶ。

**食品が少ないと採集・探索が先に返るため、穀物売却の比較へ届きにくい。** 販売開始部分の形式的な条件は食品0超だが、先行する「2食未満」の分岐が行動を返した場合には実行されない。所持金が少なく、穀物が多いだけでは、市場へ向かう理由にならない。市場を食品探索の行先としても扱っていない。

また「売却できた現金で実際にパンを取得できるか」は十分に予測していない。事前の行程評価では購入時間を仮定し、食品の有効な提示と価格・容量を確かめて買うのは市場到着後である。本人の知識で採集と売却→パンを並べて比較する処理は未実装。

## B1の記録で実際に起きたこと

調査対象は[v22の90日記録](../../fixtures/recordings/autonomous-village-energy-effort-90.v2.json.gz)。判断入力を保存判断の接頭部分から再実行した[前回の監査](FOOD_SHORTAGE_AND_ACCESS_AUDIT.md)と同じ最初の240時間を調べた。抜粋とv23の最終状態は[実測JSON](../../artifacts/v23-mortality-result.json)へ保存した。

| hour | 行動と結果 |

| 36〜39 | 食品が2食あるため再び所有畑へ。穀物3単位を積み、食事後に食品1食を持って市場へ |
| 40 | Sのパン1単位を価格1で購入。所持金は1になる |
| 41〜44 | 再び穀物3単位を提示するが、活動疲労の回復を優先して撤回し、市場の所有穀物庫へ保管 |
| 48以後 | 未加工穀物21単位、現金1が残る。食品が減ると採集・探索、身体の回復を優先し、売却開始へ戻らない |
| 132 | 野草を食べるが、以後の取得・吸収を継続できない |

従って売買機能自体は使われており、「一度も穀物を売らず、一度もパンを買わない」状態ではない。問題は、食品が減った後の切替の優先順と、加工された食品までの継続した取得行程である。残存穀物21単位は携帯0、畑14、自宅4、市場3に分かれている。売るには保管品の取得・運搬・買い手の成立が必要で、穀物や現金をそのまま栄養に変換しない。

## v23の死亡規則

- `deathOnZeroEnergy` を有効にした新fixture／rulesetを追加。内部の活動余力 `energy === 0` で、復帰不能な死亡状態にする。画面の小数2桁へ丸めた0を判定には使わない。
- 15分の身体更新、毎時の実作業消耗、初期状態を確認する。栄養残量だけを条件にせず、活動疲労によって体力0になった場合も指定通り死亡する。これは今回のゲーム規則で、人体の致死条件の校正ではない。
- `person_died` に分単位の時刻、原因となる身体Event、位置、栄養・疲労と死亡時の身体を保存する。
- 移動・作業を中断し、予約資源を解放。睡眠を終了し、未処理の本人宛刺激を取り除き、以後の自律判断を停止する。外部からの指示も拒否する。
- 販売提示を直ちに撤回。物品・現金・所有権・死者の位置は維持する。相続、死体の劣化、遺品の取得は今回追加しない。通行時の生存者との競合からは外す。
- 死者の身体時計・栄養帳簿を死亡時に固定し、生存者と植物・動物・食品腐敗の時計は進める。画面の遺品在庫は死亡後も世界の物品状態を反映する。

実装：[世界](../../packages/sim/autonomous-world.ts)、[ステータス](../../packages/sim/village-status.ts)、[Event投影](../../apps/web/village-status-replay.ts)、[記録](../../packages/sim/village-recording.ts)。旧版のfixtureでは死亡を追加せず、v22を含む旧記録の規則を保つ。

## 次の実装候補

1. **採集・穀物売却→パン・既存現金での購入を、本人の知識で同じ候補群にする。** 「手持ち2食未満」だけで売却候補が消える優先順を改める。取得・摂食・吸収までの時間、負担、食品提示の成立率、未成立時の代替と帰路を見込む。
2. 可食供給ゼロ／加工・市場の停滞／本人の見逃しを区別した対照で検証する。取得可能な食品行程を見逃したケースを直し、供給自体が不足するケースを救済係数で隠さない。
3. この小さな食品経済の整合と取得行程を確立してから、技能獲得・需要に応じた職の切替を追加する。薪・雇用の停止を継承する。

この順序は後続候補であり、v23に採集／売却の共同比較を実装済みとは扱わない。
