# v25回復行程の修正と90日試行

更新: 2026-10-23。区分: 接続試作の行動上の不備の修正・実測。[初版の接続試作](HMOSAIC_CONNECTION_V25_RESULT.md)の後続。[運用契約](../foundations/HMOSAIC_RUNTIME_CONTRACT.md)と[オブジェクト設計](../foundations/HMOSAIC_OBJECT_DESIGN.md)の境界を維持し、[形式仕様](../foundations/HMOSAIC_FORMAL_SPEC.md)の計算法は引き続き未採用。検証範囲は[STATUS](../STATUS.md)。

## 初版で見落としていた不備

初版の24時間記録ではFが825分（1日目13:45）に死亡していた。栄養備蓄23.725を残し、疲労1、活動余力0だった。hour4に自宅へ戻っても回復の候補がなく、果樹地点と自宅を往復した。hour12は疲労0.9056、hour13は0.9856で、新しい移動を開始していた。

原因は、回復の親が「自宅への移動→観察」しか提案せず、休息を含んでいなかったこと、自宅を現在地と同じとして候補から外していたこと、固定の中断ruleが開始済みの移動だけを対象にしていたことにある。仮評価も現在の不快を目的の優先度へ加えており、帰宅後に本当に不快が減る行程かを十分に比較していなかった。身体予測は待機を休息と同じ回復として扱っていたが、世界では待機中も荷物を支持し、休息とは異なる。

以前の7対照は接続・状態遷移・再現の確認だった。実走で休息を選び、疲労が下がり、初日を生き残るという行動の条件を検査していなかった。再現一致を生活としての妥当性の証拠にしてはならない。

## 修正と版の分離

| 項目 | 初版 | 今回 |
|---|---|---|
| fixture | `hierarchyV25` | `hierarchyRecoveryV25`（身体・世界設定は同一） |
| 構成 | `travel-body-prototype@1` | `travel-body-recovery@2` |
| 登録表 | `hierarchy-registry@1` | `hierarchy-registry@2` |
| ruleset | `autonomous-village-hierarchy-v25` | `autonomous-village-hierarchy-recovery-v25` |
| 回復 | 移動→観察 | その場で2時間休息、または帰宅→2時間休息→観察 |
| 身体モデル | `body-forward@1` | `body-forward@2`。待機の荷重負担と休息を分け、0時間の観察では感覚量を保持 |
| 合成・評価 | `compose@1` / `temporary-evaluation@1` | `compose@2` / `temporary-evaluation@2` |
| 画面 | 24時間 | 90日。初版24時間も比較用に残す |

回復行程を生成する責任は登録した親、予測は順モデル、経過の合成と適用域の検査は合成器、案の比較は評価器に置く。共通実行器へ「疲れているFなら休め」等の人物・親別の条件は入れない。初版のモデルと記録は置換せず、同じ人格アダプターが保存された構成版から実装を解決する。

改訂の仮評価は `優先度 − 経過時間（h）＋40×（初期疲労² − 終了疲労²）`。回復案の優先度は0とし、実際に予測した疲労減少を比較する。40は試作の仮係数。各区間の予測で疲労1以上または活動余力0以下になる行程は`predicted-capacity-exhaustion`で除外する。これは局所予測の適用域の検査であり、生存確率を比較する形式仕様の採用ではない。評価基準を`temporary-recovery-v2`として記録する。

食品の親は到着までの初版の仮案を保持する。栄養摂取の実行を完成させたものではない。制御学習・モデル内構成変更も未実装。この修正を条件別ruleからの適応・一般化の成功としない。世界の身体係数、物品、栄養、死亡条件は変更していない。

記録の再計算テストでは、読取専用の共有JSONを`structuredClone`した際に同一値の配列の参照が共有され、状態更新が別の保存項目にも反映される問題を検出した。検証済みのJSON状態を可変にする境界で参照を展開するコピーへ変更した。初版の全判断再計算とhash一致で互換を確認する。

seed240924。最初の24時間は5人とも生存し、Fは5回休息、判断時に観測した最大疲労は0.6624。テストでは世界の休息完了の証拠から実際の疲労低下も検査する。旧版のFの疲労死は再現対照として保持した。

## 追加した検査

[回復の対照](../../tests/hierarchy-recovery-v25.test.ts)を初版の7対照とは別に置いた。

1. 初版のFの疲労死、圧縮した読取専用記録からの全判断再計算、旧hashの再現。
2. 疲労0.9856の自宅／屋外、荷重0／8／16で、移動前に疲労枯渇の予測を除外し、実行可能な休息を選ぶ。
3. 荷重付き待機を回復と予測しない。0時間の観察で既知の身体感覚を消さない。
4. 世界で24時間実走し、5人の生存・Fの休息と疲労低下・予測更新・12時間保存再開・全判断再計算・身体Event投影・新記録再生を確認。
5. 10日まで延ばして残る栄養死を検出し、死亡後の本人の判断・学習・身体が停止することを確認。

90日のCLIでも通常の判断入力と共有JSONに符号化した記録の両方から全判断を再計算し、保存再開と記録再生を照合する。実行した検査と未実行はSTATUSに記す。適応・一般化や90日生活継続を合格したとは扱わない。
